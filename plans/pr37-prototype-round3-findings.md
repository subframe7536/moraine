## Cross-family findings

1. **Children are lazy structure, not a default-mode probe.** Reading props.children to compare with undefined created Items eagerly and then again under the rendered provider. Checkbox required state retained phantom registrations and RadioGroup navigation focused disconnected nodes. Property presence fixed these tested paths; explicit children={undefined} selects manual composition in the candidate. Plan 003 must settle this API and cover spreads/empty Show without JSX inspection.
2. **Provider ownership precedes part creation.** Resolving raw floating children before SurfaceContext.Provider caused missing Positioner context. Rendering children under the provider fixed it. Instantiating menu-layer cleanup outside mounted content also referenced window during SSR; the bounded candidate moves browser-only ownership into the mounted surface. Neither change fixes open-Portal server omission.
3. **A handled Escape belongs to one menu layer.** The submenu initially closed both itself and its parent. Local handling now consumes the event and global handling avoids duplicate/owned events. Chromium proves two menus become one before the parent is explicitly closed. Pointer grace, Tab and checkable/radio item parity are separate gates.
4. **Measured elements and style slots must align.** Applying the height-constrained Accordion content recipe to the measured inner Collapsible content produced zero height. Applying it to contentWrapper leaves natural inner measurement intact. The experimental CSS generator also needed the repository's colon-only variant-group expansion; default expansion corrupted h-(--size). Browser geometry needs actual generated CSS and resolved variables.
5. **Native submission is an independent assertion.** After the real reset-button click, Slider ARIA reports [20,80], but FormData reports [40,60]. Existing jsdom compatibility reset cases pass. The candidate retains the existing useSlider/useFormReset path; native reset timing/default values are the suspected boundary, not a proven root cause. Plan 029 must resolve it and verify both controlled and uncontrolled submitted values.
6. **Retain bounded reuse without claiming full engines.** InputNumber preserves parsing/raw state; Slider retains its hook; Avatar retains loading; FileUpload retains validation/native/URL handling. Select/MultiSelect share collection calculation, while value/form ownership stays with each root. CommandPalette uses a simplified flat candidate and Resizable uses explicit constraints with existing math/handle hooks: neither proves production behavior parity.

## Coverage limits and production gates

All 24 rows have source, representative runtime coverage and grouped SSR/browser evidence, but a row is not a promise that every proposed part or legacy option is implemented. No production public exports, permanent browser harness, docs/API generation migration or consumer bundle comparison was completed here. Public namespace shapes, custom-host ref/currentTarget types, all slot precedence combinations and default/manual parity still require per-family acceptance.

Only Chromium ran. Real touch/pen, Firefox/WebKit, assistive technology, Shadow DOM/other-document ownership and multiple package copies remain unverified. SidebarFrame uses a controlled breakpoint signal rather than a real viewport media-query matrix. Avatar stale-load cases use mocks. CommandPalette is flat, MultiSelect is string-only/non-virtual, and List external positioning is not a variable-height virtualizer validation. Resizable nested/intersection/collapse/dynamic controlled sizes remain unverified.

First HTML association/hydration checks do not prove initial RadioGroup keyboard entry or checkbox group validity: these still depend on client registration in the candidate. Four raw/default overlay families have an explicit server-open omission fixture; menu and other inherited Portal paths still need their own complete server acceptance matrix. The unresolved earlier ResizeObserver console error needs a stable reproduction and attribution before the browser harness can claim a clean lifecycle gate.
