## 2. Translation rules

From the fixed decisions in `plans/README.md`:

1. Port the Vega design language into Moraine's existing utility classes and semantic
   tokens. Do not copy `.z-*` class names, the registry, theme switching, CSS files,
   or any of Zaidan's other seven visual styles.
2. Treat Zaidan's `default` size as Moraine's `md`. Preserve Moraine's public
   `xs`–`xl` size surface: use Zaidan's `xs`, `sm`, `default`, and `lg` values as
   anchors, then extend `xl` by one consistent spacing/type step only where Moraine
   already exposes it. Do not add or remove public variants merely to match Zaidan.
3. Preserve Moraine behavior, DOM semantics, data/ARIA attributes, focus behavior, and
   component composition. Translate Vega selectors onto Moraine's existing state
   attributes; styling work must not replace the completed behavior-parity work. When
   a Vega selector depends on a DOM relationship Moraine does not have, record an
   intentional divergence instead of changing DOM.
4. Reuse Moraine's `surface-border`, `surface-overlay`, `effect-fv-border`,
   `effect-invalid`, and `effect-dis` shortcuts plus semantic color tokens. Use
   Moraine's semantic radius tiers (`rounded-xs`…`rounded-4xl`) rather than importing
   Zaidan's radius-variable implementation.
5. Use the existing Moraine motion primitives when they represent the same motion:
   enter defaults to 150 ms, exit to 100 ms, layout/indicator movement to 200 ms, and
   sheet movement to 200 ms. A component may deviate only when its matrix row records
   the exact Vega evidence and reason.
6. `classes` and `styles` keep their static forms. Built-in classes live in
   `{component}.class.ts`: `cva` only for real variants, static shared strings as
   `*_CLASS` constants, and state selectors as ordinary classes (no state variants in
   `cva`).
7. Moraine's comprehensive components own a mostly static render tree. For a known
   slot or optional branch, use the existing prop/accessor and apply the class at the
   final DOM owner; do not use `has-*`, `group-has-*`, or `in-data-*` to discover fixed
   structure. Pass size/variant values into existing `cva` calls or compose a direct
   class with `cn`. Keep relationship selectors only for arbitrary caller-owned
   children or runtime state that is genuinely exposed on another node.
8. Do not add presentational markers such as `data-icon`, `data-size`, or
   `data-placeholder`. Existing runtime state may keep its current `data-*`/ARIA
   vocabulary, and a new attribute is allowed only for a real semantic state. Do not
   rename slots, add visual-only nodes, split existing slots, or add ARIA solely to
   satisfy a Vega selector.
9. Rows are dispositioned `aligned` after implementation, `intentional-divergence`
   (deviation recorded in §5 with a reason), or
   `headless-no-visual-surface` (no default visual surface to port). Every row carries
   exactly one of these three classifications. A row whose current values already
   equal the Vega target is noted `already aligned` inside its audit axes and still
   links its domain plan so that plan verifies it.

### 2.1 Static composition and selector translation

The Vega selector remains in the evidence column so reviewers can see the upstream
relationship, but the implementation column must name Moraine's local owner:

| Vega relationship                                                                  | Moraine translation                                                                                                                                                                       |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `has-data-[slot=…]`, `has-[>…]`, `group-has-*` for a fixed optional slot           | Read the existing prop/accessor and add the class directly to the root or slot that owns the visual rule.                                                                                 |
| `group-data-*`, `in-data-*`, or descendant slot selectors for size/variant context | Pass the existing size/variant into the child's `cva` or compose its direct slot class; do not add a marker attribute.                                                                    |
| `data-expanded`, `data-selected`, `aria-invalid`, focus, and other runtime state   | Keep or translate to the existing state on the nearest Moraine owner; retain semantic `data-unchecked` and SidebarFrame `data-state` where exposed; do not create a second layout marker. |
| Child/sibling relationships for arbitrary caller-owned content                     | Keep the smallest existing relationship selector when the component cannot know the final child shape; preserve the current slot names.                                                   |
| Upstream visual subpart with no Moraine slot                                       | Keep the Moraine structure and record the missing subpart as an intentional divergence.                                                                                                   |

This is an implementation translation, not permission to change public slots, DOM
order, ARIA, or the visual values recorded in the scale tables.

For the rows that quote an upstream rename in their audit axes, the Moraine translation
is explicit: ButtonGroup keeps `data-slot="root"`, AvatarGroup keeps
`data-slot="item"`, Progress keeps its `status` slot, Tooltip keeps its current
content/text/Kbd tree, FormField keeps its current error semantics, and Pagination
keeps `data-current`. These divergences are intentional and do not change the recorded
visual targets or dispositions.

## 5. Intentional divergences

Registry of deliberate deviations from Vega. Rows reference these IDs instead of
re-explaining them.

- **D-001 — Control size ladder.** Vega has no 28px tier and no `xl`; it anchors
  `xs 24 / sm 32 / default 36 / lg 40` (`.z-button-size-*`, L212–225). Moraine keeps
  its public `xs`–`xl` surface, so `sm` moves from `h-7` to `h-8` and `xl` extends one
  consistent +4px step to `h-11`. Button additionally interpolates text size and
  radius per size today (`text-xs`→`text-lg`, `rounded-md`→`rounded-xl`) while Vega
  fixes `text-sm` and `rounded-md` for `sm`–`lg`; the affected rows record which
  values are realigned to the anchors and which stay as size-scaled divergences.
- **D-002 — Disabled opacity.** Vega disables via `opacity-50` (field grouping,
  `.z-checkbox` L403, `.z-field-label` L723); Moraine's `effect-dis` shortcut is
  `opacity-64 pointer-events-none` (`src/unocss/theme.ts`). Moraine keeps its
  shortcut; rows note the opacity difference explicitly.
- **D-003 — Tooltip slide distance.** Vega tooltip slides 8px (`slide-in-from-*-2`,
  L1470); Moraine's `animate-tooltip-side-*` primitive offsets `0.25rem` (4px)
  (`src/unocss/theme.ts` SEMANTIC_ANIMATION_CONFIGS). Kept as the existing primitive
  for the smaller surface; the Tooltip row carries the evidence.
- **D-004 — Enter duration.** Vega enter animations run `duration-100` for
  menus/popovers/select/combobox/tooltip/dialog (e.g. L412, L571); Moraine's enter
  primitive is fixed at 150ms by `plans/README.md`. Enter 150ms / exit 100ms is the
  sweep default; Vega's 100ms enter is recorded per row, not adopted.
- **D-005 — Surface ring.** Vega popover/menu/select surfaces use
  `ring-1 ring-foreground/10 shadow-md` (e.g. `.z-popover-content` L1002); Moraine's
  `surface-overlay` is `border border-border shadow-md` and has no
  `ring-foreground/10` token. Overlay rows use `surface-overlay`; adding a semantic
  foreground-ring token is out of scope for this ledger.
- **D-006 — Card surface.** Moraine Card root is `text-card-foreground surface-border rounded-2xl bg-card shadow-xs/5` with per-slot `p-6` padding and a `text-lg leading-none font-semibold` title
  (`src/elements/card/card.tsx`); Vega Card is
  `ring-foreground/10 bg-card text-card-foreground rounded-xl shadow-xs ring-1` with
  `--card-spacing: 24px` slot gap/padding, `data-[size=sm]` 16px, and a
  `text-base leading-normal font-medium` title (`.z-card` L363–377). The border-vs-ring
  part falls under D-005; the radius/title realignment and the `compact` → 16px
  spacing mapping are recorded on the Card row for Plan 003.
- **D-007 — Tooltip default surface.** Vega tooltip is dark by default
  (`bg-foreground text-background`, no ring/border/shadow); Moraine's default is the
  light `text-foreground surface-overlay bg-background shadow-sm` with the dark
  surface opt-in via `invert`. Moraine keeps its light default; `invert` maps to
  Vega's default. Recorded on the Tooltip row.
- **D-008 — Menu item state vocabulary.** Vega styles menu items through `:focus`
  plus `data-[variant=destructive]`, `data-inset`, and `data-disabled:opacity-50`;
  Moraine emits `data-highlighted`/`data-selected`/`data-disabled` and a `color` cva
  variant, and has no `data-inset` concept (grid layout). Moraine's attributes are
  translated, not replaced; Vega's `data-inset:pl-8` has no Moraine target.
- **D-009 — Popper logical sides.** Vega defines `data-[side=inline-start|inline-end]`
  logical selectors (`.z-popover-content-logical` L1005, `.z-hover-card-content-logical`
  L751); Moraine resolves only physical `top|right|bottom|left`
  (`resolveOverlayMenuSide`). Physical-only resolution is kept; logical-side support
  is a DOM/behavior change, out of scope for the styling sweep.
- **D-010 — Open-state attribute.** Vega popover/hover-card bind `data-open`
  (`data-closed` for exit); Moraine's overlay machinery emits `data-expanded`/
  `data-closed` everywhere and never `data-open`. Motion binds to Moraine's existing
  attributes (`data-expanded` + side variant classes); emitting `data-open` is a DOM
  change recorded here, not performed by a styling row.
- **D-011 — Static composition and selector topology.** Vega's primitive wrappers use
  `has-*`, `group-*`, `in-data-*`, and slot markers to discover optional children,
  context sizes, and nested composition. Moraine's comprehensive components already
  own those branches, so equivalent visual classes are applied directly from existing
  props/accessors at the final slot. Existing runtime state attributes remain valid,
  including Switch `data-unchecked` and SidebarFrame `data-state`; existing Button and
  Badge `data-size`/`data-variant` attributes are unchanged. New presentational
  markers, slot renames, visual-only nodes, Progress status splitting, Tooltip arrows,
  and styling-only ARIA additions are not ported.
