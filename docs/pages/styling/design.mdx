Moraine decouples component layout and logic from design tokens using semantic CSS variables. Changing a variable in your application stylesheet updates every Moraine component without altering component classes or JSX templates.

## CSS variables

Set your design tokens in your application stylesheet under `:root` for light mode and `.dark` for dark mode. Both the UnoCSS preset and the Tailwind CSS plugin map these variables to standard utility classes (`bg-primary`, `text-foreground`, `rounded-md`, etc.).

Set `--radius`, `--spacing`, or `--font-size` on a container to change the matching utilities inside that subtree. `--font-size` is the base for the `text-xs` through `text-9xl` sizes and their default line heights.

```css title="src/theme.css"
:root {
  --background: oklch(100% 0 0);
  --foreground: oklch(20% 0 0);
  --primary: oklch(55% 0.2 260);
  --primary-foreground: white;
  --secondary: oklch(96% 0 0);
  --secondary-foreground: oklch(20% 0 0);
  --card: oklch(99% 0 0);
  --card-foreground: oklch(20% 0 0);
  --popover: oklch(100% 0 0);
  --popover-foreground: oklch(20% 0 0);
  --muted: oklch(96% 0 0);
  --muted-foreground: oklch(50% 0 0);
  --accent: oklch(96% 0 0);
  --accent-foreground: oklch(20% 0 0);
  --destructive: oklch(62% 0.22 25);
  --destructive-foreground: white;
  --border: oklch(90% 0 0);
  --input: oklch(90% 0 0);
  --ring: oklch(55% 0.2 260);
  --radius: 0.625rem;
  --spacing: 0.25rem;
  --font-size: 1rem;
}

.dark {
  --background: oklch(18% 0 0);
  --foreground: oklch(96% 0 0);
  --primary: oklch(70% 0.16 260);
  --primary-foreground: oklch(18% 0 0);
  --secondary: oklch(26% 0 0);
  --secondary-foreground: oklch(96% 0 0);
  --card: oklch(22% 0 0);
  --card-foreground: oklch(96% 0 0);
  --popover: oklch(20% 0 0);
  --popover-foreground: oklch(96% 0 0);
  --muted: oklch(26% 0 0);
  --muted-foreground: oklch(65% 0 0);
  --accent: oklch(26% 0 0);
  --accent-foreground: oklch(96% 0 0);
  --destructive: oklch(65% 0.22 25);
  --destructive-foreground: oklch(18% 0 0);
  --border: oklch(32% 0 0);
  --input: oklch(32% 0 0);
  --ring: oklch(70% 0.16 260);
}
```

### Surface colors and contrast pairing

Surface colors always pair with corresponding `-foreground` variables to ensure guaranteed contrast for text, icons, and indicators:

| Role            | Surface token   | Foreground token           | Primary use                                                 |
| :-------------- | :-------------- | :------------------------- | :---------------------------------------------------------- |
| **Page**        | `--background`  | `--foreground`             | Default viewport canvas and readable body text.             |
| **Primary**     | `--primary`     | `--primary-foreground`     | High-emphasis actions, active selections, focus rings.      |
| **Secondary**   | `--secondary`   | `--secondary-foreground`   | Secondary action buttons, subtle badges.                    |
| **Card**        | `--card`        | `--card-foreground`        | Grouped containers, cards, tables.                          |
| **Popover**     | `--popover`     | `--popover-foreground`     | Floating overlays, menus, tooltips, dialogs.                |
| **Muted**       | `--muted`       | `--muted-foreground`       | Subtle backgrounds, secondary descriptions, disabled state. |
| **Accent**      | `--accent`      | `--accent-foreground`      | Hover states, tab indicators, highlighted list items.       |
| **Destructive** | `--destructive` | `--destructive-foreground` | Irreversible actions, error banners, validation errors.     |

### Interactive state cascade

For the 8 surface colors, Moraine supports dedicated `--*-hover` and `--*-active` variables. When omitted, they cascade naturally:

- If `--<color>-hover` is not defined, it falls back to `--<color>`.
- If `--<color>-active` is not defined, it falls back to `--<color>-hover`, then `--<color>`.

If you use UnoCSS, [`presetMoraine({ colorVariables })`](/styling/unocss#color-variables) can automatically synthesize these states using CSS `color-mix()`.

## Border radius scale

Moraine computes a responsive radius scale from the base `--radius` variable. Changing `--radius` scales every component corner radius proportionally:

| Utility       | Formula                     | Computed value (with `--radius: 0.625rem`) |
| :------------ | :-------------------------- | :----------------------------------------- |
| `rounded-xs`  | `calc(var(--radius) * 0.5)` | `0.3125rem` (`5px`)                        |
| `rounded-sm`  | `calc(var(--radius) * 0.6)` | `0.375rem` (`6px`)                         |
| `rounded-md`  | `calc(var(--radius) * 0.8)` | `0.5rem` (`8px`)                           |
| `rounded-lg`  | `var(--radius)`             | `0.625rem` (`10px`)                        |
| `rounded-xl`  | `calc(var(--radius) * 1.4)` | `0.875rem` (`14px`)                        |
| `rounded-2xl` | `calc(var(--radius) * 1.8)` | `1.125rem` (`18px`)                        |
| `rounded-3xl` | `calc(var(--radius) * 2.2)` | `1.375rem` (`22px`)                        |
| `rounded-4xl` | `calc(var(--radius) * 2.6)` | `1.625rem` (`26px`)                        |

## Box shadow scale

Moraine components map shadow utilities to these CSS variables:

| Utility      | Token          | Typical use                    |
| :----------- | :------------- | :----------------------------- |
| `shadow-2xs` | `--shadow-2xs` | Subtle borders and inset lines |
| `shadow-xs`  | `--shadow-xs`  | Buttons, badges                |
| `shadow-sm`  | `--shadow-sm`  | Cards, input fields            |
| `shadow`     | `--shadow`     | Default raised surfaces        |
| `shadow-md`  | `--shadow-md`  | Dropdowns, popovers            |
| `shadow-lg`  | `--shadow-lg`  | Dialogs, modals                |
| `shadow-xl`  | `--shadow-xl`  | Drawers, sheets                |
| `shadow-2xl` | `--shadow-2xl` | Deep floating overlays         |

## Typography and dimensions

| Token             | Description                     | Fallback                   |
| :---------------- | :------------------------------ | :------------------------- |
| `--font-sans`     | Primary UI typeface             | System sans-serif stack    |
| `--font-mono`     | Code, numbers, and Kbd          | System monospace stack     |
| `--font-serif`    | Editorial serif typeface        | System serif stack         |
| `--font-size`     | Base for `text-xs`–`text-9xl`   | `1rem`                     |
| `--spacing`       | Base spacing unit               | `0.25rem`                  |
| `--sidebar-width` | Width of `SidebarFrame.Sidebar` | `clamp(14rem, 25%, 20rem)` |

## Semantic z-index utilities

Moraine avoids arbitrary numeric z-indices in favor of a 7-tier semantic scale:

| Utility      | Value | Scope                              |
| :----------- | ----: | :--------------------------------- |
| `z-base`     |   `1` | Base elevated content              |
| `z-raised`   |   `2` | Raised content and ranges          |
| `z-control`  |   `3` | Controls above local ranges        |
| `z-sticky`   |  `10` | Sticky headers and rails           |
| `z-resize`   |  `20` | Splitter and resize handles        |
| `z-overlay`  |  `40` | Backdrop masks and overlay scrims  |
| `z-floating` |  `50` | Dialogs, popovers, menus, tooltips |

## Built-in icons

Moraine includes built-in mask styles for Lucide icons. Import `moraine/icon.css` if you want zero-config icon support:

```css
@import 'moraine/icon.css';
```

Use `<Icon name="icon-search" />` or specify icon names directly in component props (`leading="i-lucide:search"` or `leading="icon-search"`).
