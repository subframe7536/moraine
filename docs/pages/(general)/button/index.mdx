## Import

```tsx
import { Button } from 'moraine'
import type { ButtonT } from 'moraine'
```

## Features

- **Polymorphic Rendering**: Render as a `<button>`, anchor, or custom Solid component while retaining Moraine styling.
- **Optional Promise-Driven Loading**: Set `loadingAuto` to derive loading state from a promise-returning `onClick`. It is disabled by default.
- **Stable Loading Focus**: Loading buttons block activation while remaining focusable, so async actions do not reset keyboard position.
- **Controlled Loading**: Use `loading` directly when loading state comes from external state.
- **Loading Placement**: The loading icon replaces the leading icon first, or the trailing icon when no leading icon is present.
- **Icon Buttons**: Icon-only sizes are available; provide `aria-label` or another accessible name for icon-only controls.
- **Semantic Variants**: Includes `default`, `secondary`, `outline`, `ghost`, `destructive`, and `link`.

## Anatomy

```text
root (<button> or polymorphic element)
├── leading (icon, image, or loading indicator)
├── label (button content)
└── trailing (icon or custom trailing content)
```

- `root`: Interactive element with hover, active, disabled, and focus-visible states.
- `leading`: Leading adornment; may be replaced by the loading icon.
- `trailing`: Trailing adornment; may be replaced by the loading icon when no leading adornment exists.

## Usage

### Loading

Use `loading` when application state owns the pending operation. `loadingAuto` is opt-in: when enabled, a promise returned by `onClick` drives the visual loading state. Loading suppresses additional activation without applying native `disabled`, so a focused button keeps its keyboard position. Explicit `disabled` still uses native disabled semantics where available.

<Preview path="./loading-usage" />

### Icons and polymorphism

Leading and trailing content can be icons or custom elements. Icon-only buttons need `aria-label` or another accessible name. Polymorphic roots without native link semantics receive button role and keyboard activation; anchors with `href` keep native link behavior. When a custom component forwards its root ref, Moraine resolves native button semantics from the rendered DOM element.

<Preview path="./icons-polymorphism" />

### Keyboard interaction

Native button keyboard behavior applies when the rendered root is a button. Non-link polymorphic roots receive button semantics and Enter/Space activation; anchors with `href` preserve native link keyboard behavior.

| Key                                 | Description                                     |
| ----------------------------------- | ----------------------------------------------- |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Activates a native button when it is focused.   |
| <kbd>Tab</kbd>                      | Moves focus to the button when it is focusable. |
