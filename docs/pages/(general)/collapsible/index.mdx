## Import

```tsx
import { Collapsible } from 'moraine'
import type { CollapsibleT } from 'moraine'
```

Use Collapsible for one disclosure whose trigger and content belong to the surrounding layout. Use [Accordion](/accordion) when several disclosures share selection rules.

## Anatomy

```text
Collapsible (root, state provider)
├── Collapsible.Trigger (trigger)
└── internal content wrapper (not configurable)
    └── Collapsible.Content (content)
```

## Usage

### Styling

Configure `root`, `trigger`, and `content` through `collapsible.base` in your Theme. The Content element exposes `data-expanded`, `data-closed`, and `data-transition` for state styling. Collapsible also renders an internal wrapper for measurement, height animation, presence, and accessibility; you cannot configure that wrapper through Theme, `classes`, `styles`, or Content props.

Root `classes` and `styles` set defaults for this Collapsible. Use direct `class` and `style` on the root, Trigger, or Content to style those elements. Content's `ref` and `as` apply to the inner Content element. `CollapsibleT.Slot`, `CollapsibleT.Classes`, and `CollapsibleT.Styles` type the slot overrides. There are no visual variants. See [Styling](/styling/overrides#override-component-styles) for override precedence.

<Preview path="./design-styling" />

### State ownership

Use `open` with `onOpenChange` for controlled state, or `defaultOpen` when the component owns its initial state. The trigger and content primitives may be composed into a custom layout.

<Preview path="./state-ownership" />

### Content lifetime

The content transition and mount behavior are separate choices. Keep content mounted when it holds state that should survive closing; unmount it when inactive content should leave the document.

<Preview path="./content-lifetime" />

### Keyboard interaction

The trigger uses button semantics by default. A polymorphic trigger follows the keyboard semantics of its supplied element or component.
