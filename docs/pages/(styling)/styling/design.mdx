## CSS variables

Like [shadcn/ui's CSS-variable theming](https://ui.shadcn.com/docs/theming), Moraine's built-in classes use semantic names such as `bg-primary`, `text-foreground`, and `rounded-lg`. The UnoCSS preset and Tailwind plugin map those classes to CSS variables that your application defines. They do not provide a default color palette. Moraine reads the following variables:

| Role              | CSS variables                                                                                                         |
| ----------------- | --------------------------------------------------------------------------------------------------------------------- |
| Page              | `--background`, `--foreground`                                                                                        |
| Primary           | `--primary`, `--primary-foreground`                                                                                   |
| Secondary         | `--secondary`, `--secondary-foreground`                                                                               |
| Card              | `--card`, `--card-foreground`                                                                                         |
| Popover           | `--popover`, `--popover-foreground`                                                                                   |
| Muted             | `--muted`, `--muted-foreground`                                                                                       |
| Accent            | `--accent`, `--accent-foreground`                                                                                     |
| Destructive       | `--destructive`, `--destructive-foreground`                                                                           |
| Borders and focus | `--border`, `--input`, `--ring`                                                                                       |
| Radius            | `--radius`                                                                                                            |
| Fonts             | `--font-sans`, `--font-mono`, `--font-serif`                                                                          |
| Shadows           | `--shadow`, `--shadow-2xs`, `--shadow-xs`, `--shadow-sm`, `--shadow-md`, `--shadow-lg`, `--shadow-xl`, `--shadow-2xl` |
| Sidebar width     | `--sidebar-width` (optional)                                                                                          |

`--radius` controls the `rounded-*` scale. `--sidebar-width` falls back to `clamp(14rem,25%,20rem)` when omitted.

Define the values in your application stylesheet and override them for dark mode or a subtree. For example, this sets only some of the tokens; add the others used by your components:

```css
:root {
  --background: oklch(100% 0 0);
  --foreground: oklch(20% 0 0);
  --primary: oklch(55% 0.2 260);
  --primary-foreground: white;
  --radius: 0.625rem;
}

.dark {
  --background: oklch(18% 0 0);
  --foreground: oklch(96% 0 0);
  --primary: oklch(70% 0.16 260);
  --primary-foreground: oklch(18% 0 0);
}
```

For the eight surface colors above, optional `--*-hover` and `--*-active` variables control interaction states. Each hover value falls back to its base; each active value falls back to hover, then base. The UnoCSS [`colorVariables` option](/styling/unocss#color-variables) can generate semantic **color** variables from supplied light and dark values; it does not supply radius, shadow, or font values. Component-specific measurement and animation variables such as `--mo-collapsible-content-height` and `--mo-anim-duration` serve different purposes.

## Interactive color tokens

Use the same semantic color tokens when styling your own interactive surfaces:

```tsx
<button class="bg-primary hover:bg-primary-hover active:bg-primary-active text-primary-foreground">
  Continue
</button>
```

## Semantic z-index utilities

| Utility      | Value | Typical use                      |
| ------------ | ----: | -------------------------------- |
| `z-base`     |     1 | Base elevated content            |
| `z-raised`   |     2 | Raised content and ranges        |
| `z-control`  |     3 | Controls above local ranges      |
| `z-sticky`   |    10 | Sticky content                   |
| `z-resize`   |    20 | Resize affordances               |
| `z-overlay`  |    40 | Overlay layers                   |
| `z-floating` |    50 | Dialogs, menus, and other popups |

## Icons

`moraine/icon.css` is an optional runtime mask asset. It is independent of component utility generation and does not replace the required Tailwind plugin or UnoCSS preset.

```css
@import 'moraine/icon.css';
```

You may instead configure an engine icon integration such as `@iconify/tailwind`. In either case, keep the Moraine plugin or preset and the published-distribution scan.
