Moraine's styling system architecture uses atomic utility classes in the published Design recipes. Your application's CSS engine must scan those classes and load Moraine's theme integration. Moraine does not ship precompiled component CSS.

## UnoCSS

Use either the Wind4 or Wind3 preset with `presetMoraine()`, and include Moraine's published JavaScript in the content scan.

```ts title="unocss.config.ts (Wind4)" {1,5} group-id="unocss"
import { defineConfig, presetWind4 } from '@subf/unocss'
import { presetMoraine } from 'moraine/unocss'

export default defineConfig({
  presets: [presetWind4(), presetMoraine()],
  content: {
    filesystem: ['./node_modules/moraine/dist/**/*.{mjs,jsx}'],
  },
})
```

```ts title="unocss.config.ts (Wind3)" {1,5} group-id="unocss"
import { defineConfig, presetWind3 } from '@subf/unocss'
import { presetMoraine } from 'moraine/unocss'

export default defineConfig({
  presets: [presetWind3(), presetMoraine()],
  content: {
    filesystem: ['./node_modules/moraine/dist/**/*.{mjs,jsx}'],
  },
})
```

The preset registers Moraine theme tokens, shared animations, semantic z-index values, and `data-*` / `aria-*` variants. `globalStyles` defaults to `true`.

### Color variables

The preset can generate light and dark semantic variables. Nothing is emitted unless `colorVariables` is configured; selectors default to `:root` and `.dark`.

```ts
presetMoraine({
  colorVariables: {
    light: {
      foreground: 'oklch(20% 0 0)',
      primary: {
        DEFAULT: 'oklch(55% 0.2 260)',
        foreground: 'white',
        hover: 8,
        active: ({ base, foreground }) => `color-mix(in oklch, ${base}, ${foreground} 16%)`,
      },
      border: 'oklch(90% 0 0)',
    },
    dark: {
      foreground: 'oklch(96% 0 0)',
      primary: {
        DEFAULT: 'oklch(70% 0.16 260)',
        foreground: 'oklch(18% 0 0)',
      },
      border: 'oklch(32% 0 0)',
    },
    hoverAdjustment: 6,
    activeAdjustment: 12,
  },
})
```

## Tailwind CSS v4

Register the plugin and scan the published distribution. The `@source` path is relative to the stylesheet containing it, so adjust the leading `..` for your project layout.

```css
@import 'tailwindcss';
@plugin 'moraine/tailwind';
@source '../node_modules/moraine/dist';
```

`@source "moraine"` is not valid: Tailwind requires a resolvable source path. The plugin provides the same colors, typography, radius, shadows, animations, z-index values, and state variants as the UnoCSS preset.

## Icons

`moraine/icon.css` is an optional runtime mask asset. It is independent of component utility generation and does not replace the required Tailwind plugin or UnoCSS preset.

```css
@import 'moraine/icon.css';
```

You may instead configure an engine icon integration such as `@iconify/tailwind`. In either case, keep the Moraine plugin or preset and the published-distribution scan.

## Motion duration variables

```css
:root {
  --mo-anim-duration: 180ms;
  --mo-anim-duration-enter: 150ms;
  --mo-anim-duration-exit: 100ms;
  --mo-anim-duration-loop: 2s;
  --mo-anim-duration-spin: 1s;
}
```

The general variable overrides every Moraine motion effect. The semantic variables target entry, exit, looping, and spinner animations separately.

## Interactive color tokens

Interactive surfaces use semantic `hover` and `active` colors. Each hover token falls back to its base color; each active token falls back to hover and then base.

```tsx
<button class="bg-primary hover:bg-primary-hover active:bg-primary-active text-primary-foreground">
  Continue
</button>
```

## Semantic z-index utilities

| Utility      | Value | Typical use                      |
| ------------ | ----: | -------------------------------- |
| `z-base`     |     1 | Base elevated content            |
| `z-raised`   |     2 | Raised content and ranges        |
| `z-control`  |     3 | Controls above local ranges      |
| `z-sticky`   |    10 | Sticky content                   |
| `z-resize`   |    20 | Resize affordances               |
| `z-overlay`  |    40 | Overlay layers                   |
| `z-floating` |    50 | Dialogs, menus, and other popups |

## Override component styles

Moraine resolves presentation from the active Design, composition-group overrides, component state, and component-instance overrides, in that order. Instance `class` and `style` win for the DOM element that owns them; `classes` and `styles` target named slots on multi-slot components.

Root-only components (`Icon`, `Kbd`, `Separator`, and the bound `form.Form`) accept direct `class` and `style` only. Their shared defaults remain configurable through the corresponding Design root entry, such as `icon.base.root` or `form.base.root`.

Overlay roots own behavior and children, not DOM attributes. Put trigger attributes on `Dialog.Trigger`, and content attributes and shell slots on `Dialog.Content` (likewise for the other overlay families).

```tsx
<Button class="bg-red-500" style={{ borderColor: 'red' }} classes={{ label: 'text-white' }}>
  Continue
</Button>
```

Pass CSS property objects to `style` and `styles` props.

## Design and MoraineProvider

Create a Design once at your application boundary. `createDesign()` includes the official recipes; passing overrides extends them. The provider requires a Design and does not load the official preset itself.

```tsx
import type { ParentProps } from 'solid-js'
import { MoraineProvider } from 'moraine'
import { createDesign } from 'moraine/design'

const design = createDesign({
  button: {
    defaultVariants: { size: 'sm' },
    base: { root: 'rounded-xl shadow-xs' },
  },
  badge: { defaultVariants: { variant: 'outline' } },
})

export function App(props: ParentProps) {
  return <MoraineProvider design={design}>{props.children}</MoraineProvider>
}
```

Each component accepts `base`, `variants`, `compoundVariants`, and `defaultVariants`. Base and variant values map named slots to utility classes. Inline styles remain instance props.

Use `createDesign({ preset: false })` for a complete unstyled slot skeleton, or `createDesign({ extends: parentDesign, button: { ... } })` for explicit inheritance. A nested provider replaces the parent Design; it does not merge automatically. Changing its `design` signal updates existing DOM without remounting components.

Without a provider, components retain behavior and accessibility but render unstyled. Development builds warn once per owner tree. The CSS integrations supply tokens and motion utilities without changing the host application's default transition duration or easing.

### Reactive replacement and native refs

Named callback refs such as `inputRef` and `textareaRef` target the editable native element; the ordinary `ref` continues to target the component root. Use callbacks for named refs rather than relying on JSX variable-assignment shorthand. Design replacement preserves those nodes and their state.

## `cn`

`cn()` combines conditional class values and resolves supported utility conflicts. It does not generate CSS, scan component files, load the plugin or preset, or validate theme tokens.

```ts
import { cn } from 'moraine'

cn('px-2 bg-primary', active && 'bg-primary-active')
```
