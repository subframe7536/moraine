Moraine's styling system architecture uses atomic utility classes in the official Theme recipes. Your application's CSS engine must scan those classes and load Moraine's theme integration. Moraine does not ship precompiled component CSS.

## UnoCSS

Use either the Wind4 or Wind3 preset with `presetMoraine()`, and include Moraine's published JavaScript in the content scan.

```ts title="unocss.config.ts (Wind4)" {1,5} group-id="unocss"
import { defineConfig, presetWind4 } from '@subf/unocss'
import { presetMoraine } from 'moraine/unocss'

export default defineConfig({
  presets: [presetWind4(), presetMoraine()],
  content: {
    filesystem: ['./node_modules/moraine/dist/**/*.{mjs,jsx}'],
  },
})
```

```ts title="unocss.config.ts (Wind3)" {1,5} group-id="unocss"
import { defineConfig, presetWind3 } from '@subf/unocss'
import { presetMoraine } from 'moraine/unocss'

export default defineConfig({
  presets: [presetWind3(), presetMoraine()],
  content: {
    filesystem: ['./node_modules/moraine/dist/**/*.{mjs,jsx}'],
  },
})
```

The preset registers Moraine theme tokens, shared animations, semantic z-index values, and `data-*` / `aria-*` variants. `globalStyles` defaults to `true`.

### Color variables

The preset can generate light and dark semantic variables. Nothing is emitted unless `colorVariables` is configured; selectors default to `:root` and `.dark`.

```ts
presetMoraine({
  colorVariables: {
    light: {
      foreground: 'oklch(20% 0 0)',
      primary: {
        DEFAULT: 'oklch(55% 0.2 260)',
        foreground: 'white',
        hover: 8,
        active: ({ base, foreground }) => `color-mix(in oklch, ${base}, ${foreground} 16%)`,
      },
      border: 'oklch(90% 0 0)',
    },
    dark: {
      foreground: 'oklch(96% 0 0)',
      primary: {
        DEFAULT: 'oklch(70% 0.16 260)',
        foreground: 'oklch(18% 0 0)',
      },
      border: 'oklch(32% 0 0)',
    },
    hoverAdjustment: 6,
    activeAdjustment: 12,
  },
})
```

## Tailwind CSS v4

Register the plugin and scan the published distribution. The `@source` path is relative to the stylesheet containing it, so adjust the leading `..` for your project layout.

```css
@import 'tailwindcss';
@plugin 'moraine/tailwind';
@source '../node_modules/moraine/dist';
```

`@source "moraine"` is not valid: Tailwind requires a resolvable source path. The plugin provides the same colors, typography, radius, shadows, animations, z-index values, and state variants as the UnoCSS preset.

## Icons

`moraine/icon.css` is an optional runtime mask asset. It is independent of component utility generation and does not replace the required Tailwind plugin or UnoCSS preset.

```css
@import 'moraine/icon.css';
```

You may instead configure an engine icon integration such as `@iconify/tailwind`. In either case, keep the Moraine plugin or preset and the published-distribution scan.

## Animation duration variables

```css
:root {
  --mo-anim-duration: 180ms;
  --mo-anim-duration-enter: 150ms;
  --mo-anim-duration-exit: 100ms;
  --mo-anim-duration-loop: 2s;
  --mo-anim-duration-spin: 1s;
}
```

The general variable overrides every Moraine CSS animation. The semantic variables target entry, exit, looping, and spinner animations separately. CSS transitions retain the duration and timing function configured by the host Tailwind CSS or UnoCSS setup.

## Interactive color tokens

Interactive surfaces use semantic `hover` and `active` colors. Each hover token falls back to its base color; each active token falls back to hover and then base.

```tsx
<button class="bg-primary hover:bg-primary-hover active:bg-primary-active text-primary-foreground">
  Continue
</button>
```

## Semantic z-index utilities

| Utility      | Value | Typical use                      |
| ------------ | ----: | -------------------------------- |
| `z-base`     |     1 | Base elevated content            |
| `z-raised`   |     2 | Raised content and ranges        |
| `z-control`  |     3 | Controls above local ranges      |
| `z-sticky`   |    10 | Sticky content                   |
| `z-resize`   |    20 | Resize affordances               |
| `z-overlay`  |    40 | Overlay layers                   |
| `z-floating` |    50 | Dialogs, menus, and other popups |

## Override component styles

Theme classes merge in layer order, followed by composition-group overrides, instance `classes`, and root `class`. Inline styles merge dynamic geometry, group `styles`, instance `styles`, and root `style`. Pass CSS property objects to inline style props.

```tsx
<Button class="bg-red-500" style={{ borderColor: 'red' }} classes={{ label: 'text-white' }}>
  Continue
</Button>
```

Root-only components (`Icon`, `Kbd`, `Separator`, and the bound `form.Form`) expose direct `class` and `style`. Their Theme entries still have a `root` slot. Overlay roots own behavior and children; put DOM attributes and presentation on their Trigger and Content parts.

## Component kinds

The `Single` or `Composite` label in each component page header comes from its `XxxT.Kind` type. It describes how you compose the component, not how many DOM elements or presentation slots it renders.

**Single** components expose their configuration through one component's props. `Card` is single even though it has header, body, and footer slots; `ButtonGroup` is single even though it groups children. Apply root styles with `class` and `style`, and use `classes` and `styles` for named slots when the component supports them.

```tsx
<Card title="Account" class="max-w-md" classes={{ body: 'space-y-4' }}>
  Account settings
</Card>
```

**Composite** components expose attached parts that you arrange explicitly. Styling belongs to the root or part that owns the corresponding DOM. `SidebarFrame` renders a layout root and accepts family slot overrides, while each part also accepts its own `class` and `style`.

```tsx
<SidebarFrame class="h-80" classes={{ sidebar: 'bg-muted' }}>
  <SidebarFrame.Sidebar>
    <SidebarFrame.SidebarBody class="p-4">Navigation</SidebarFrame.SidebarBody>
  </SidebarFrame.Sidebar>
  <SidebarFrame.Main class="p-6">Workspace</SidebarFrame.Main>
</SidebarFrame>
```

`Dialog` also has a composite API, but its root only provides state and context. Put presentation on `Dialog.Trigger` and `Dialog.Content`; the root has no DOM element to style.

```tsx
<Dialog>
  <Dialog.Trigger class="font-semibold">Edit profile</Dialog.Trigger>
  <Dialog.Content title="Profile" class="max-w-lg" classes={{ body: 'space-y-4' }}>
    Profile settings
  </Dialog.Content>
</Dialog>
```

The bound `form.Form` is single: `createForm()` returns separate `Form` and `Field` components, rather than attaching parts to `form.Form`. A kind label does not imply support for particular style props; each component's API lists the supported overrides.

## Theme layers and Providers

Place `<MoraineProvider>` at the application root to enable the official presentation. It needs no Theme prop. `createTheme()` creates an empty sparse layer collection and imports no official recipes.

```tsx
import { Button, MoraineProvider, MoraineUnstyledProvider } from 'moraine'
import { createTheme } from 'moraine/theme'

const compact = createTheme({
  button: { defaults: { size: 'sm' }, base: { root: 'rounded-xl' } },
})
const brand = createTheme({
  extends: compact,
  button: { base: { root: 'font-semibold' } },
})

<MoraineProvider theme={brand}>
  <Button>Official + compact + brand</Button>
  <MoraineProvider theme={createTheme({ button: { base: { root: 'shadow-md' } } })}>
    <Button>Appended shadow</Button>
  </MoraineProvider>
  <MoraineUnstyledProvider>
    <Button>Behavior with no presentation</Button>
    <MoraineProvider theme={compact}>
      <Button>Only compact presentation</Button>
    </MoraineProvider>
  </MoraineUnstyledProvider>
</MoraineProvider>
```

`extends` accepts one parent Theme, preserving its ordered layers before appending the child’s non-empty layer. There is no recursive configuration merge. Nested providers append custom layers without duplicating the official Theme. An unstyled boundary discards all inherited layers, and a styled provider below it inherits that reset.

Components outside a Provider remain functional and unstyled. Development builds warn once per owner tree; production and tests do not warn.

### Recipes and defaults

A component Theme entry accepts `base`, `variants`, `compoundVariants`, and `defaults`. Each class contribution targets named slots. Missing families and slots allocate no empty Recipe or slot inventory.

```ts
const theme = createTheme({
  button: {
    defaults: { size: 'sm' },
    variants: { size: { sm: { label: 'tracking-wide' } } },
    compoundVariants: [{ size: 'sm', variant: 'outline', class: { root: 'border-2' } }],
  },
})
```

Visual values resolve from explicit instance props, inherited composition/FormField values, and finally the latest Theme default. Only `undefined` falls back. `null` suppresses the default and selects no branch; `false`, `0`, and `''` remain explicit values where the Variant type supports them. All layers use the same final visual values.

For standalone recipe authoring, `slotRecipe` produces slot-class maps and `atomicRecipe` produces one class string. Both are exported from `moraine/theme`, accept `defaults`, and expose readonly `.options` metadata. Neither chooses a factory based on the shape of `base`.

### State selectors

Recipe Variants describe stable component options that select class branches, including visual treatments and configured layout or interaction modes. Transient disabled, required, selected, open/closed, loading, orientation, and placement state use the component's documented data/ARIA attributes. Keep state selectors flat so both CSS engines can scan them:

```ts
const theme = createTheme({
  button: { base: { root: 'data-disabled:opacity-50 data-loading:cursor-wait' } },
  select: { variants: { search: { true: { control: 'focus-within:ring-2' } } } },
  popover: { base: { content: 'data-[side=bottom]:mt-2' } },
})
```

Measurements such as slider percentages and floating transform origins remain inline styles or CSS variables.

### Reactive replacement and native refs

Changing a Provider's `theme` updates classes without remounting component DOM. Input and Textarea keep their values, focus, selection, and refs. Their ordinary `ref` targets the wrapper; callback `inputRef` and `textareaRef` target the editable native control.

## `cn`

`cn()` combines conditional class values and resolves supported utility conflicts. It does not generate CSS, scan component files, load the plugin or preset, or validate theme tokens.

```ts
import { cn } from 'moraine'

cn('px-2 bg-primary', active && 'bg-primary-active')
```
