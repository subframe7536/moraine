## Overview

Moraine exposes types in two layers:

- **`XxxProps`** — the top-level public props type for each component, exported directly from `moraine`.
- **`XxxT.*`** — a namespace of component-specific sub-types (items, values, slots, etc.), also exported from `moraine`.

```tsx
import type { ButtonProps, SelectProps, SelectT } from 'moraine'
```

## Component Props (`XxxProps`)

Every component exports a `Props` type named after the component (e.g. `ButtonProps`, `SelectProps`). Use this when wrapping a component or extending its props interface.

```tsx
import type { ButtonProps } from 'moraine'

interface PrimaryButtonProps extends ButtonProps {
  trackingId?: string
}

function PrimaryButton(props: PrimaryButtonProps) {
  // ...
}
```

## Root props

Components with a DOM root document that root through their public types. Some composite primitives, such as `Modal`, are state providers and expose their DOM through subcomponents instead of rendering a root element themselves.

DOM roots expose precise native Solid attributes by default. Unknown attributes fail type checking, while `data-*` and ARIA attributes remain supported. Polymorphic `as` preserves required custom-component props and the native root's ref/event types.

```tsx
<Card aria-describedby="details" data-testid="card" />
<Button as="a" href="/docs" ref={(anchor) => anchor.focus()}>Docs</Button>
```

Lowercase event aliases and Solid directive prefixes are excluded from ordinary root props. Use camelCase native event handlers.

### Input and Textarea native ownership

Native attributes such as `form`, `list`, `enterkeyhint`, and `aria-label`, together with clipboard, composition, keyboard, and validation handlers, go to the editable element. Root `class`, `style`, and `ref` belong to the wrapper. Use `inputRef` or `textareaRef` for a native control ref.

```tsx
<Input
  form="checkout"
  list="cities"
  inputRef={(input) => input.select()}
  onChange={(event) => console.log(event.currentTarget.value)}
  onValueChange={(value) => console.log(value)}
/>
```

`onValueChange` is the normalized-value callback, including model modifiers. `onInput`, `onChange`, `onBlur`, and `onFocus` receive native events after internal synchronization and FormField notification. A caller handler's `preventDefault()` does not undo those earlier steps.

Explicit control identity and boolean state override FormField values, including `false`. Caller `aria-describedby` and `aria-labelledby` tokens come first, followed by generated IDs with duplicates removed. Explicit scalar ARIA values take precedence over generated values.

## Component Namespace (`XxxT`)

The `XxxT` namespace groups all supporting types for a component under a single import. This keeps the top-level exports focused and avoids polluting the global type space.

### Component kinds

Every public component namespace declares `Kind` as a literal type. `'single'` describes a component configured through its own props; `'composite'` describes a component with attached parts, such as `Dialog.Trigger` and `Dialog.Content`, that you compose explicitly.

```ts
import type { ButtonT, DialogT, FormT } from 'moraine'

type ButtonKind = ButtonT.Kind // 'single'
type DialogKind = DialogT.Kind // 'composite'
type BoundFormKind = FormT.Kind // 'single': describes form.Form
```

`Kind` is type-only metadata, not a prop or a runtime component property. Component documentation generates its header label from this declaration. Slot count, `children`, and a `Group` suffix do not determine the kind. See [Component kinds](/styling#component-kinds) for styling examples.

### Item models

List-like components (e.g. `Select`, `MultiSelect`) expose an `Item` type for their option objects.

```tsx
import type { SelectT } from 'moraine'

const regionOptions: SelectT.Item[] = [
  { label: 'Asia', value: 'asia' },
  { label: 'Europe', value: 'europe' },
]
```

### Controlled values

Use `XxxT.Value` to type state variables that hold a component's selected or active value.

```tsx
import type { SelectT } from 'moraine'

let selected: SelectT.Value | null = null
```

### Render callback params

Prop callbacks often receive component-specific objects. Type them using the appropriate namespace member.

```tsx
import type { SelectProps } from 'moraine'

const labelRender: SelectProps['labelRender'] = (option) =>
  typeof option.label === 'string' ? option.label : (option.key ?? 'Unknown')
```

### Slot types

`XxxT.Slot<T>` documents each named presentation slot. Use `keyof XxxT.Slot` when a slot-key union is needed. `Classes` and `Styles` specialize the values for class names and CSS objects while retaining slot documentation. A presentation slot may be virtual, such as a loading class applied to an existing icon.

```tsx
import type { CardT } from 'moraine'

const overrides: CardT.Classes = {
  header: 'bg-gray-100',
}
```

## Namespace Reference

Each `XxxT` namespace may expose the following members depending on the component:

| Member    | Description                                              |
| --------- | -------------------------------------------------------- |
| `Kind`    | Component composition model: `'single'` or `'composite'` |
| `Slot`    | Generic documented map of presentation slots             |
| `Variant` | Nullable visual options; `null` suppresses a default     |
| `Item`    | Data model for list items or option objects              |
| `Value`   | Domain type of the component's controlled value          |
| `Classes` | Typed map from slot name to CSS class string             |
| `Styles`  | Typed map from slot name to inline style object          |
| `Base`    | Component-specific base/business props                   |
| `Props`   | Final public props shape (same as `XxxProps`)            |

## Tips

- Use `import type` for all type-only imports to keep runtime bundles clean.
- Prefer exported `XxxProps` and `XxxT.*` types over importing internal source types directly.
- When in doubt, start with `XxxProps`; reach for `XxxT.*` only when you need a more specific sub-type.
