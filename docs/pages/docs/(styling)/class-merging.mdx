Moraine includes a class merger built on [cn](https://github.com/shadcn-ui/cn) and preconfigured for UnoCSS and Tailwind CSS v4. It resolves conflicting utility classes (such as `p-2` vs `p-4`, or `bg-primary` vs `bg-muted`) and understands Moraine's semantic shadows, z-index, text size, tone, and parametric transform utilities.

Class inputs accept `cn`'s `ClassValue` type (strings, arrays, and conditional objects). An empty merge returns `undefined` so empty `class` attributes are omitted from the DOM.

## Merging Classes

```tsx
import { cn } from 'moraine'

// Conflicting padding resolves to the last applied class ('p-4'):
const className = cn('p-2 text-sm', 'p-4 text-foreground')
// => "text-sm p-4 text-foreground"
```

- `cn(...)` always uses Moraine's default conflict rules and ignores `MoraineProvider`.
- `useCn()` reads the merger from the nearest `MoraineProvider` (including custom `cnConfig` rules).
- Keep UnoCSS's automatic class sorting enabled. Pass overrides as later arguments to `cn(...)` or through the [4-layer override hierarchy](/docs/customization#the-4-layer-override-hierarchy) rather than putting competing utilities (`p-2 p-4`) inside the same string literal.

## Custom Class Conflict Rules

If your project adds utility classes that conflict with each other (such as custom density or brand utilities), teach the merger about them with `createCn` or `MoraineProvider`:

```ts title="src/lib/app-cn.ts"
import { createCn } from 'moraine'
import type { CnConfig } from 'moraine'

export const appCnConfig = {
  extend: {
    classGroups: {
      density: ['density-roomy', 'density-compact'],
    },
  },
} satisfies CnConfig

const appCn = createCn(appCnConfig)

const className = appCn('density-roomy', 'density-compact')
// => "density-compact"
```

`CnConfig` is the `cn` library's configuration extension, so besides `extend` it also accepts `override`, `prefix`, and `cacheSize`. `createCn` applies it on top of the library defaults and Moraine's rules.

## Scoping with `MoraineProvider`

Pass your `cnConfig` to `MoraineProvider` so that every nested Moraine component and every `useCn()` call uses your conflict rules:

```tsx title="src/App.tsx"
import { Button, MoraineProvider, useCn } from 'moraine'
import { appCnConfig } from './lib/app-cn'

function DensityExample() {
  const scopedCn = useCn()

  return (
    <div class={scopedCn('density-roomy', 'density-compact')}>
      {/* Button uses the nearest provider's merger */}
      <Button class="density-roomy density-compact">Compact Action</Button>
    </div>
  )
}

export function App() {
  return (
    <MoraineProvider cnConfig={appCnConfig}>
      <DensityExample />
    </MoraineProvider>
  )
}
```

A nested provider without `cnConfig` inherits the parent merger. A `cnConfig` object replaces it with the Moraine defaults plus that config, without the parent's extensions, so `cnConfig={{}}` restores the defaults. See [Nesting and reset rules](/docs/provider#nesting-and-reset-rules).
