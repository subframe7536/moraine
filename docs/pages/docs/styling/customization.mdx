Moraine provides a granular customization architecture. Rather than forcing you to choose between monolithic CSS classes or unstyled headless HTML, every Moraine component exposes typed slots and deterministic override layers.

<Preview path="./customization-layers" />

## The 4-layer override hierarchy

When styling a component, choose the layer that matches your required scope:

| Layer | Surface            | Scope                           | How to configure                                           |
| :---: | :----------------- | :------------------------------ | :--------------------------------------------------------- |
| **1** | **Base Recipe**    | Library defaults                | Default styles shipped with Moraine.                       |
| **2** | **Theme Layer**    | Application or subtree defaults | Wrap in `<MoraineProvider theme={defineTheme(...)}>`       |
| **3** | **Instance Slots** | Named slots on one instance     | `classes={{ slot: '...' }}` / `styles={{ slot: { ... } }}` |
| **4** | **Direct Element** | Target DOM element on a part    | `class="..."` / `style={{ ... }}` directly on the part     |

### How classes merge across layers

Classes merge in ascending order (Layer 1 → Layer 2 → Layer 3 → Layer 4) using Moraine's configured `cn` merger. Conflicting Tailwind/UnoCSS classes (such as `p-2` vs `p-4` or `bg-primary` vs `bg-muted`) are resolved intelligently: the higher layer wins. Non-conflicting utility classes (such as `rounded-full` alongside `p-4`) are combined.

```tsx
// Layer 4 direct class overrides the button's background and adds shadow,
// while Layer 3 classes.label customizes the inner text slot:
<Button
  class="bg-destructive hover:bg-destructive-hover shadow-lg"
  classes={{ label: 'tracking-widest uppercase font-mono' }}
>
  Confirm Deletion
</Button>
```

See [Composition](/docs/composition) for the distinction between public parts and style slots.

## Style slots and the `data-slot` contract

### CamelCase in TSX props

In TypeScript JSX, slot names are always typed in camelCase on `classes` and `styles` objects:

```tsx
<Select
  classes={{
    control: 'rounded-xl border-primary/50',
    item: 'py-2 px-3',
    itemLabel: 'font-semibold',
  }}
/>
```

### Kebab-case `data-slot` in DOM

In the rendered DOM, Moraine marks every element with a standardized kebab-case `data-slot` attribute:

- Root elements: `data-slot="<component>"` (e.g. `data-slot="select"`, `data-slot="button"`).
- Child slots: `data-slot="<component>-<slot>"` (e.g. `data-slot="select-control"`, `data-slot="select-item-label"`).

This contract enables clean, robust CSS selectors and testing queries:

```css
/* Target all Moraine select controls across your application */
[data-slot='select-control'] {
  backdrop-filter: blur(8px);
}
```

## TypeScript slot types

Moraine exports typed slot and classes shapes under each component namespace:

```ts
import type { ButtonT, CardT, DialogT } from 'moraine'

// Type-safe slot classes map
const buttonClasses: ButtonT.Classes = {
  root: 'rounded-full',
  label: 'tracking-wide',
}

// All available slot names as a union
type CardSlotNames = CardT.Slot // 'root' | 'header' | 'title' | 'description' | 'action' | 'body' | 'footer'
```
