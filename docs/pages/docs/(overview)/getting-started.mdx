Moraine provides styled SolidJS components for forms, navigation, overlays, and content.
Components use utility classes and semantic CSS variables, with setup for UnoCSS or Tailwind CSS.

Moraine is pre-1.0; breaking changes may occur.

## Set up your application

1. [Install Moraine](/docs/installation) in your SolidJS application.
2. Configure [UnoCSS](/docs/unocss) or [Tailwind CSS](/docs/tailwind) to generate component styles.
3. [Choose a component](/components) and copy its Usage example.

## Read a component page

Each page starts with a Playground, then Usage with when to use the component and a copyable
example. Usage also explains state, composition, and behavior. Anatomy and Examples follow when
useful. The generated API reference lists attributes and props from the library source.

Components such as `Button`, `Input`, and `Select` use one JSX entry point. Components such as
`Dialog` and `Card` expose attached parts that you arrange yourself. Read
[Composition](/docs/composition) for parts, slots, and DOM ownership, and
[Polymorphism](/docs/polymorphism) before changing a rendered element with `as`.

## Adapt the styles

Use `class` and object `style` props for local changes. Use slot `classes` and `styles` where the
component exposes them, or scope shared recipe overrides with `defineTheme()` and `MoraineProvider`.
Start with [Customization](/docs/customization), then see [Theming](/docs/theming) for shared overrides
and [Design tokens](/docs/design) for colors, spacing, and dimensions.

## Integrate behavior

Use [Form](/components/form) for schema validation and submission, or
[Field](/components/field) for standalone labels and messages. The
[Accessibility guide](/docs/accessibility) explains naming and focus responsibilities; the
[SSR guide](/docs/ssr) covers initial state, IDs, and browser-only content.
