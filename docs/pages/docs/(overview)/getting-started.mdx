Moraine is a comprehensive SolidJS component library combining accessible, headless behavioral primitives with ready-to-use atomic class styling inspired by Nuxt UI and Shadcn.

Moraine supports reactive props, server rendering, and hydration in SolidJS applications.

## Fine-Grained Reactivity First

Moraine embraces SolidJS signals, memos, and ownership scopes as first-class citizens:

- **No Virtual DOM Overhead**: Components execute once during creation and bind directly to the real DOM.
- **Reactive Prop Access**: Props and controlled states remain fully reactive without defensive prop-tracking wrappers.
- **SSR & Hydration Safety**: Built-in deterministic IDs via `createId`, hydration-safe portals, and transition presence management for SolidStart and Vite SSR.

## Headless Behaviors with Ready-to-Use Styling

You don't have to choose between writing accessibility from scratch or being locked into a rigid design system:

- **WAI-ARIA Compliance**: Automatic keyboard navigation (roving `tabIndex`), focus trapping in dialogs, and ARIA state attribute management (`aria-expanded`, `aria-selected`, `aria-activedescendant`).
- **Atomic Class Styling**: Styled with composable utility classes powered by official presets and plugins for both [UnoCSS](/docs/unocss) and [Tailwind CSS](/docs/tailwind). No CSS-in-JS runtime overhead.

## Composable Anatomy & Polymorphism

- **Single vs Composite**: Components like `Button`, `Input`, and `Select` expose one JSX entry point. Components like `Dialog`, `Card`, and `SidebarFrame` expose attached parts that you arrange in your layout (`Dialog.Trigger`, `Dialog.Content`, `Dialog.Close`).
- **Render Delegation (`as`)**: Components and parts that expose `as` can render native HTML elements (`as="a"`) or other components (`as={Button}`) with typed, forwarded props.

## Multi-Layer Customization

Moraine merges four styling layers in increasing priority: built-in recipes, `defineTheme()` overrides, instance slot `classes` / `styles`, and direct part `class` / `style` props. Use `MoraineProvider` to scope a component theme to the application or a subtree.

Semantic CSS variables are a separate styling surface: configure colors, radiuses, shadows, and dimensions across your application without changing component recipes. See [Customization](/docs/customization) for the override hierarchy and [Design Tokens](/docs/design) for variable roles.
