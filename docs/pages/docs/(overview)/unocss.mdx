Moraine provides first-class support for UnoCSS through the `presetMoraine()` preset exported from `moraine/unocss`. It maps semantic colors, border radiuses, shadows, animation keyframes, z-index utilities, and state variants directly into UnoCSS.

## Installation and config

Add `presetMoraine()` to your `unocss.config.ts` alongside your preferred Wind preset (`presetWind4` or `presetWind3`):

```ts title="unocss.config.ts (Wind4)" {2,5,8} group-id="unocss"
import { defineConfig, presetWind4 } from '@subf/unocss'
import { presetMoraine } from 'moraine/unocss'

export default defineConfig({
  presets: [presetWind4(), presetMoraine()],
  content: {
    pipeline: {
      include: [/\.(?:mjs|js|ts|jsx|tsx|mdx?|html)(?:\?|$)/],
    },
  },
})
```

```ts title="unocss.config.ts (Wind3)" {2,5,8} group-id="unocss"
import { defineConfig, presetWind3 } from '@subf/unocss'
import { presetMoraine } from 'moraine/unocss'

export default defineConfig({
  presets: [presetWind3(), presetMoraine()],
  content: {
    pipeline: {
      include: [/\.(?:mjs|js|ts|jsx|tsx|mdx?|html)(?:\?|$)/],
    },
  },
})
```

### Scanning component classes

Moraine publishes component classes in `.mjs` and `.jsx` files. UnoCSS extracts classes from imported modules in the build pipeline, but its default filter omits `.mjs` and `.ts`. The examples include both alongside common app file types. Keep the extensions your app uses when changing `pipeline.include` because it replaces the default filter. See [UnoCSS's extraction guide](https://unocss.dev/guide/extracting) for details.

Moraine expands variant groups in its published component classes. If your own app uses grouped utilities such as `hover:(bg-primary text-primary-foreground)`, add `transformerVariantGroup()` from `@subf/unocss` to your `transformers` array.

## Preset options

`presetMoraine()` provides Moraine's utility tokens, state variants, and neutral light and dark colors as RGB/RGBA values. The default selectors are `:root` and `.dark`. Configure shared fonts and single-value tokens at the top level; put colors and shadows in named `override` entries.

```ts
presetMoraine({
  fonts: { sans: 'Inter, sans-serif', mono: 'monospace' },
  radius: '0.625rem',
  fontSize: '1rem',
  spacing: '0.25rem',
  sidebarWidth: '18rem',
  override: {
    light: {
      shadows: { sm: '0 1px 2px rgba(0, 0, 0, 0.05)' },
      colors: {
        primary: { base: '#2563eb', foreground: '#fff' },
      },
    },
    dark: {
      colors: {
        primary: { base: '#60a5fa', foreground: '#172554', hover: '#93c5fd' },
      },
    },
    brand: {
      selector: '[data-theme="brand"]',
      colors: { primary: '#7c3aed' },
    },
  },
})
```

| Option          | Default                    | Behavior                                                                                                      |
| :-------------- | :------------------------- | :------------------------------------------------------------------------------------------------------------ |
| `themeDefaults` | `true`                     | Emits neutral light/dark colors and HTML background/text styles. Set `false` when your CSS defines the theme. |
| `override`      | omitted                    | Overrides the built-in neutral light and dark colors or adds named themes.                                    |
| `colorStates`   | `{ hover: 8, active: 12 }` | Generates missing hover and active colors for configured base colors. Set `false` to disable.                 |

### Theme tokens

Color strings are shorthand for `{ base: value }`. Expand a color to override `foreground`, `hover`, or `active` without repeating `base`. Available color names and fields match Moraine's semantic colors. Colors and shadows belong inside named `override` entries. `fonts` supports `sans`, `mono`, and `serif`; `shadows` supports `base`, `2xs`, `xs`, `sm`, `md`, `lg`, `xl`, and `2xl`. Single values use `radius`, `fontSize`, `spacing`, and `sidebarWidth`. Other custom properties belong in your CSS file.

`light` and `dark` default to `:root` and `.dark`. Another name defaults to `[data-theme="name"]`; set `selector` on any entry to use a complete CSS selector. The preset emits the default light colors first, then dark colors, then custom themes in configuration order. Light and dark overrides merge with their respective defaults. A partial custom theme inherits missing variables through the CSS cascade, including variables used by portaled overlays when they are declared on an ancestor of the portal.

### Hover and active colors

When `color-mix(in oklch, …)` is supported, missing states mix the color toward its foreground in the scope where the utility is used. `background` uses the global foreground; other colors use their own foreground with the global foreground as a fallback. An explicit state variable always wins. An explicit state can be a CSS color, a mixing percentage, or a callback:

```ts
presetMoraine({
  colorStates: { hover: 6 }, // active keeps the default 12%
  override: {
    light: {
      colors: {
        primary: {
          base: '#2563eb',
          hover: '#1d4ed8',
          active: ({ selector, color, state, base, foreground, adjustment }) =>
            `color-mix(in oklch, ${base}, ${foreground} ${adjustment ?? 12}%)`,
        },
        secondary: { hover: 5 },
      },
    },
  },
})
```

The callback receives its selector, color name, state, configured base or CSS variable reference, foreground value or reference, and current adjustment. Percentages must be finite values from 0 to 100. `colorStates: false` stops automatic generation; explicit states still emit. Generated utilities retain their CSS fallbacks: active → hover → base.

In browsers without `color-mix()`, the built-in neutral themes use precomputed RGB hover and active colors, including numeric state overrides when their colors are plain RGB. Custom themes and colors that cannot be computed ahead of time fall back to their base color unless you provide explicit state colors. Use a widely supported CSS color string when an explicit state must work in older browsers. When you paste a complete shadcn/ui palette into your stylesheet, disable the built-in palette:

```ts
presetMoraine({ themeDefaults: false })
```

Define your `:root` and `.dark` variables in CSS as usual. You can add `--primary-hover` and other state variables there when older browsers need a distinct state color. `baseStyles` has been removed; `themeDefaults` is its replacement and also controls the built-in colors.
