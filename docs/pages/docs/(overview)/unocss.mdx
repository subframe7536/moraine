Moraine provides first-class support for UnoCSS through the `presetMoraine()` preset exported from `moraine/unocss`. It maps semantic colors, border radiuses, shadows, animation keyframes, z-index utilities, and state variants directly into UnoCSS.

## Installation and config

Add `presetMoraine()` to your `unocss.config.ts` alongside your preferred Wind preset (`presetWind4` or `presetWind3`):

```ts title="unocss.config.ts (Wind4)" {2,6,11-13} group-id="unocss"
import { defineConfig, presetWind4, transformerVariantGroup } from '@subf/unocss'
import { presetMoraine } from 'moraine/unocss'

export default defineConfig({
  presets: [presetWind4(), presetMoraine()],
  transformers: [transformerVariantGroup()],
  content: {
    filesystem: ['./node_modules/moraine/dist/**/*.{mjs,jsx}'],
    // Crucial: UnoCSS ignores .ts files by default.
    // Include .ts to scan recipe files and compiled subpath entries.
    pipeline: {
      include: [/\.(?:ts|tsx|mdx)(?:\?|$)/],
    },
  },
})
```

```ts title="unocss.config.ts (Wind3)" {2,6,11-13} group-id="unocss"
import { defineConfig, presetWind3, transformerVariantGroup } from '@subf/unocss'
import { presetMoraine } from 'moraine/unocss'

export default defineConfig({
  presets: [presetWind3(), presetMoraine()],
  transformers: [transformerVariantGroup()],
  content: {
    filesystem: ['./node_modules/moraine/dist/**/*.{mjs,jsx}'],
    pipeline: {
      include: [/\.(?:ts|tsx|mdx)(?:\?|$)/],
    },
  },
})
```

### Critical: File scanning pipeline

By default, UnoCSS's extraction pipeline only scans `.html`, `.jsx`, `.tsx`, `.vue`, and `.svelte` files. Because Moraine recipes and style classes can be defined or imported from TypeScript (`.ts`) files, you **must** configure `content.pipeline.include` to include `/\.(?:ts|tsx|mdx)(?:\?|$)/`. Without this, UnoCSS will not scan classes defined inside `.ts` recipe files.

### Variant grouping transformer

Moraine's recipes and templates use UnoCSS's parenthesized variant groups (such as `hover:(bg-primary text-white)`). Add `transformerVariantGroup()` from `@subf/unocss` or `@unocss/transformer-variant-group` to your transformers array.

## Preset options

`presetMoraine()` provides Moraine's utility tokens and state variants. Its optional `themes` setting emits CSS custom properties grouped by selector. Omit it when your application already defines those properties in CSS.

```ts
presetMoraine({
  baseStyles: true,
  colorStates: { hover: 8, active: 12 },
  themes: {
    ':root': {
      colors: {
        background: '#fff',
        foreground: '#18181b',
        primary: { base: '#2563eb', foreground: '#fff' },
        secondary: '#f4f4f5',
      },
      fonts: { sans: 'Inter, sans-serif', mono: 'monospace' },
      shadows: { sm: '0 1px 2px rgb(0 0 0 / 0.05)' },
      radius: '0.625rem',
      fontSize: '1rem',
      spacing: '0.25rem',
      sidebarWidth: '18rem',
    },
    '.dark': {
      colors: {
        background: '#18181b',
        foreground: '#fafafa',
        primary: { base: '#60a5fa', foreground: '#172554', hover: '#93c5fd' },
      },
    },
  },
})
```

| Option        | Default                    | Behavior                                                                                      |
| :------------ | :------------------------- | :-------------------------------------------------------------------------------------------- |
| `baseStyles`  | `true`                     | Adds HTML background and foreground styles. Set `false` if your app owns them.                |
| `themes`      | omitted                    | Emits only the configured Moraine token variables for each CSS selector.                      |
| `colorStates` | `{ hover: 8, active: 12 }` | Generates missing hover and active colors for configured base colors. Set `false` to disable. |

### Theme tokens

Color strings are shorthand for `{ base: value }`. Expand a color to override `foreground`, `hover`, or `active` without repeating `base`. Available color names and fields match Moraine's semantic colors. `fonts` supports `sans`, `mono`, and `serif`; `shadows` supports `base`, `2xs`, `xs`, `sm`, `md`, `lg`, `xl`, and `2xl`. Single values use `radius`, `fontSize`, `spacing`, and `sidebarWidth`. Other custom properties belong in your CSS file.

Selectors such as `:root`, `.dark`, and `[data-theme="brand"]` are emitted in configuration order. A partial theme inherits missing variables through the CSS cascade, including variables used by portaled overlays when they are declared on an ancestor of the portal.

### Hover and active colors

For each color with a configured base, missing states use `color-mix(in oklch, …)` toward its foreground. `background` uses the global foreground; other colors use their own foreground with the global foreground as a fallback. An explicit state can be a CSS color, a mixing percentage, or a callback:

```ts
presetMoraine({
  colorStates: { hover: 6 }, // active keeps the default 12%
  themes: {
    ':root': {
      colors: {
        primary: {
          base: '#2563eb',
          hover: '#1d4ed8',
          active: ({ selector, color, state, base, foreground, adjustment }) =>
            `color-mix(in oklch, ${base}, ${foreground} ${adjustment ?? 12}%)`,
        },
        secondary: { hover: 5 },
      },
    },
  },
})
```

The callback receives its selector, color name, state, configured base or CSS variable reference, foreground value or reference, and current adjustment. Percentages must be finite values from 0 to 100. `colorStates: false` stops automatic generation; explicit states still emit. Generated utilities retain their CSS fallbacks: active → hover → base.

The former `globalStyles` and `colorVariables` options have been removed. Tailwind users define theme variables in CSS; this preset option applies to UnoCSS only.
