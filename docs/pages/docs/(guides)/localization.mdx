Moraine components ship English accessible names, placeholders, and locale-sensitive parsing. Without a `MoraineProvider`, `locale` is `en-US`. A root provider follows the browser after hydration (`detectLocale` defaults to `true`); SSR and the first client render stay `en-US`. Add a provider to replace the copy, pin a BCP 47 locale such as `zh-CN`, pass `detectLocale={false}` to keep `en-US`, or override direction. Nest a provider to override part of the tree.

## Provider props

| Prop           | Omitted                                                               | Set                                                                                                                                                                   |
| :------------- | :-------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `locale`       | Inherits the parent locale, or `en-US` without a provider.            | Replaces it with a BCP 47 tag such as `de-DE` or `zh-CN`. Always wins over `detectLocale`.                                                                            |
| `detectLocale` | `true` on the root provider; nested providers inherit the parent tag. | After hydration, follow `navigator.language` and `languagechange`. SSR and the first client render stay `en-US`. `false` keeps `en-US`. Ignored when `locale` is set. |
| `dir`          | Inherits the parent direction, or `<html dir>` / the document.        | Replaces it with `ltr` or `rtl`, or `null` to clear back to document detection.                                                                                       |
| `messages`     | Inherits the parent message pack.                                     | Deep-merges a partial pack over the parent. The base pack is English.                                                                                                 |

Set `lang` and `dir` on `<html>` for document language and CSS/layout. Pass the same `dir` to `MoraineProvider` when portaled overlays should copy it onto their content. A component's own `dir` attribute always wins over the provider, and the provider wins over `<html dir>`.

`locale` is shared application locale context. `InputNumber` uses it for `Intl.NumberFormat` parsing and formatting. Collection search, typeahead, and the command palette use `Intl.Collator`. `InputNumber` reads `locale` from its own prop, then falls back to the provider, then `en-US`. Invalid locale tags fall back to `en-US` for both `Intl.NumberFormat` and `Intl.Collator`.

A root `MoraineProvider` follows the browser after hydration. Nested providers that omit `locale` inherit the parent's already resolved tag and do not detect again. Pass `detectLocale={false}` to keep `en-US`, or pass an explicit `locale` from a cookie or `Accept-Language` in production so formatted values do not flash from `en-US` to the browser language.

```tsx title="src/App.tsx"
import { MoraineProvider } from 'moraine'
import type { MoraineMessagesInput } from 'moraine'

const zhCN = {
  dialog: { close: '关闭' },
  pagination: {
    label: '分页',
    status: ({ page, total }) => `第 ${page} 页，共 ${total} 页`,
    page: ({ page, total }) => `第 ${page} 页，共 ${total} 页`,
    currentPage: ({ page, total }) => `第 ${page} 页，共 ${total} 页，当前页`,
    prev: ({ page }) => (page === undefined ? '上一页' : `上一页，第 ${page} 页`),
    next: ({ page }) => (page === undefined ? '下一页' : `下一页，第 ${page} 页`),
  },
} satisfies MoraineMessagesInput

export function App(props) {
  return (
    <MoraineProvider locale="zh-CN" dir="ltr" messages={zhCN}>
      {props.children}
    </MoraineProvider>
  )
}
```

Changing `messages`, `locale`, or `dir` updates the rendered text and behavior without remounting the components. `useLocale()` returns stable `locale()` and `dir()` accessors for application code that needs the same values.

A component prop always wins over the pack. `placeholder`, `aria-label`, `ariaLabel`, and `label` keep the caller's text, and the pack fills only what the caller left unset.

## Message packs

`MoraineMessages` is the full English shape. `MoraineMessagesInput` is the deep-partial type you pass to the provider. Groups are `dialog`, `sheet`, `breadcrumb`, `commandPalette`, `select`, `combobox`, `multiSelect`, `slider`, `pagination`, `inputNumber`, `fileUpload`, `tagsField`, `resizable`, `sidebarFrame`, `form`, and `kbd`.

Text that includes a number or a name is a function, so the translation controls word order:

```ts
const pagination = {
  prev: ({ page }) => (page === undefined ? '上一页' : `上一页，第 ${page} 页`),
}
```

`page` is omitted when the control is already on that edge. Plural rules stay in the pack, for example with `Intl.PluralRules`:

```ts
const rules = new Intl.PluralRules('en-US')

const pagination = {
  page: ({ page, total }) =>
    rules.select(total) === 'one'
      ? `Go to page ${page} of ${total} page`
      : `Go to page ${page} of ${total} pages`,
}
```

`kbd` is a record of accessible names for the built-in key aliases. The keycap symbol stays the same; only the announced name changes.

## Direction

`dir` on `MoraineProvider` controls Moraine component direction-sensitive behavior, such as horizontal keyboard navigation, slider interaction direction, and portaled overlay positioning. It does not set a `dir` attribute on arbitrary descendants. Set `dir` on `<html>` when you need the browser's full RTL layout behavior.

Portaled popover, dialog, and sheet content receive `dir` from the provider when the component does not set `dir` itself. The attribute is omitted when neither the provider nor the component sets it, so server markup stays unchanged until you opt in, and inlined content follows `<html dir>`.
