Drag and drop reordering comes from an optional adapter in `moraine/dnd`. Components have no drag
props. A sortable composes through the render prop that already owns each row element, so it adds
nothing to components that are not reordered.

| Adapter              | Use it with                                                                     |
| -------------------- | ------------------------------------------------------------------------------- |
| `createListSortable` | `List`, `DataTable` rows, and any flat collection whose row elements you render |
| `createSortable`     | Custom collections that need their own drop rules                               |

## Installation

<CodeTabs package="@dnd-kit/solid" />

Only `moraine/dnd` imports `@dnd-kit/solid`. The main `moraine` entry does not, so apps that do not
reorder anything do not need the package.

## List

```tsx
import { List } from 'moraine'
import { createListSortable } from 'moraine/dnd'

const [items, setItems] = createSignal(initialItems)
const sortable = createListSortable({
  items,
  onReorder: (event) => setItems(event.items),
})

<sortable.Provider>
  <List
    items={items()}
    itemRender={(context) => {
      const row = sortable.useRow(context)
      return (
        <li {...row.props}>
          <button ref={row.handleRef} aria-label={`Reorder ${context.item.label}`}>
            ⋮⋮
          </button>
          {context.item.label}
        </li>
      )
    }}
  />
</sortable.Provider>
```

- `items` is an accessor for the items in rendered order.
- `onReorder` receives the moved `item`, its `from` and `to` indexes, and `items`, a copy of the
  collection with the move applied. A drop that leaves the item where it was reports nothing.
- `useRow(context)` takes the row `index` and optional `props` from the render context.
  `row.props` keeps those props, composes the drag ref into their `ref`, and adds the drag state
  attributes. Spread it onto the outer row element.
- Mount `sortable.Provider` once, around the component that renders the rows.

## DataTable

`DataTable` takes the row registration through `rowProps`, and a cell can render the handle with
`handleRefFor`:

```tsx
const sortable = createListSortable({
  items: () => table.getRowModel().rows,
  getId: (row) => row.id,
  onReorder: (event) => setData(event.items.map((row) => row.original)),
})

// In a column: cell: (props) => <button ref={sortable.handleRefFor(props.row.id)}>⋮⋮</button>

<sortable.Provider>
  <DataTable table={table} rowProps={(context) => sortable.useRow(context).props} />
</sortable.Provider>
```

Read [DataTable drag to reorder rows](/components/data-table#drag-to-reorder-rows) for sorting,
pagination, and sub-rows. Columns reorder the same way through `headProps`, with
`orientation: 'horizontal'` and `table.getVisibleLeafColumns()` as `items`.

## Tree

`createTreeSortable(tree, { onMove })` registers items through `itemRender`. Spread
`sortable.useNode(item).props` onto `tree.Item`. Rows accept drops before, after, and, when
`canNest` allows it, inside. Read [Tree drag to move items](/components/tree#drag-to-move-items)
for the drop rules, auto-expansion, and `moveTreeNode`.

## How it works

### Rows stay in place

Rows do not move while dragging. The dragged row stays in place as a copy, a second copy follows
the pointer, and the row under the pointer is marked as the drop target:

| Attribute            | Element                       | Value                                                                  |
| -------------------- | ----------------------------- | ---------------------------------------------------------------------- |
| `data-dragging`      | Dragged row and both copies   | Present while it is dragged                                            |
| `data-dnd-dragging`  | Copy that follows the pointer | Set by dnd kit; style it, for example `data-[dnd-dragging]:opacity-60` |
| `data-drop-position` | Row under it                  | `before` or `after`, from the pointer's half of the row                |

Style the drop indicator from these attributes. For example, draw a line on the matching edge:

```tsx
<li
  {...row.props}
  class="data-[drop-position=before]:shadow-[inset_0_2px_0_var(--primary)] data-[drop-position=after]:shadow-[inset_0_-2px_0_var(--primary)]"
/>
```

Keeping rows in place lets a sortable work with rows that Solid or a virtualizer owns, and keeps
row state such as focus intact until the drop. When the drag ends, the moved row slides from where
it was released into its new place, also when the host renders it as a new element. Canceled drags
slide back the same way. Pass `dropAnimation: { duration, easing }` to tune it, or `false` to turn
it off; it is skipped under `prefers-reduced-motion`.

### Drag handles

Without `row.handleRef`, the whole row starts a drag once the mouse moves 5 pixels, or after a
200 ms press, so clicks on the row still work. Touch drags start after a 250 ms press. Pass
`row.handleRef` to an element such as a grip button to start drags only from that element; a
mouse drag from a handle starts immediately.

### Keyboard

Focus the handle, or a focusable row without one, and press Space or Enter to pick it up. Arrow
keys move to the next row; the side is the direction of travel. Space or Enter drops the row, and
Escape cancels the drag. Screen readers hear dnd kit's announcements for each step.

### Virtualization

Pass `sortable.rangeExtractor` to the virtualizer. It renders the visible range plus overscan, like
the default extractor, and adds the dragged row while it is scrolled out of view. Dragging near
the edge of the scroll container scrolls it.

`createTableVirtualizer` takes the same option.

```tsx
const virtualizer = createListVirtualizer<Item>({
  estimateSize: () => 36,
  getItemKey: (item) => item.id,
  rangeExtractor: sortable.rangeExtractor,
})
```

Pass `getItemKey` with a stable id so measured row sizes follow their items after a move.

## Options

`createListSortable` and `createSortable` forward these options to dnd kit's `DragDropProvider`:

| Option      | Description                                                                                    |
| ----------- | ---------------------------------------------------------------------------------------------- |
| `sensors`   | Input sensors. An array replaces the pointer and keyboard defaults; a function extends them.   |
| `plugins`   | Plugins such as announcements, auto-scroll, and drag feedback. An array replaces the defaults. |
| `modifiers` | Movement modifiers, such as restricting the drag to one axis.                                  |

```tsx
import { PointerSensor } from '@dnd-kit/solid'

// Pointer dragging only, without keyboard dragging.
const sortable = createListSortable({ items, onReorder, sensors: [PointerSensor] })
```

`createListSortable` also takes:

- `getId(item, index)`: a stable id, used by `handleRefFor`. Defaults to the index.
- `orientation`: `'horizontal'` for items laid out in a row, such as chips. `before` and `after`
  then come from the inline start and end halves of an item, mirrored in right-to-left layouts.
- `isDisabled(item, index)`: keeps a row from being dragged or dropped on.
- `canDrop(source, target, position)`: rejects a drop location before it shows an indicator.

`onReorder` also receives the `target` item and the `position` (`before` or `after`) for data that
is not a flat array. `moveItem(items, from, to)` returns a moved copy of an array.

## Custom collections

`createSortable({ canDrop, onDrop })` is the layer under `createListSortable`. Register each item
element with `sortable.useItem({ id, index, positions })` and spread `item.attributes` onto it.
`positions` can include `inside` for items that accept children. `onDrop` receives the source and
target ids and the position; `canDrop` rejects a location before it shows an indicator.

## Common pitfalls

- Update the items in `onReorder`. The sortable does not reorder them itself.
- Spread `row.props` on the outer row element, not an inner one, so the drop target covers the
  whole row and virtual row measurement keeps working.
- The server renders rows without drag behavior; rows become draggable after hydration.
