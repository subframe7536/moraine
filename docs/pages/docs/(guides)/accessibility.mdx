Accessibility (A11y) is a first-class requirement across Moraine. Every primitive adheres to the [W3C WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/) standard, providing keyboard navigation, focus management, and screen reader announcements out of the box.

## Keyboard Interaction Models

Moraine components implement predictable keyboard contracts based on established UI patterns:

### Roving Tabindex & Collections

In composite collections such as `Tabs`, `Select`, `Combobox`, and `DropdownMenu`, only the active item is in the browser's tab order (`tabindex="0"`), while other items use `tabindex="-1"`. Users navigate between items using arrow keys without cluttering the document tab flow:

| Key                                 | Action                                                 |
| ----------------------------------- | ------------------------------------------------------ |
| <kbd>↓</kbd> / <kbd>→</kbd>         | Moves focus to the next item (with automatic looping). |
| <kbd>↑</kbd> / <kbd>←</kbd>         | Moves focus to the previous item.                      |
| <kbd>Home</kbd>                     | Moves focus directly to the first enabled item.        |
| <kbd>End</kbd>                      | Moves focus directly to the last enabled item.         |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Activates or selects the highlighted item.             |

### Overlay Dismissal

All dismissible overlays (`Dialog`, `Sheet`, `Popover`, `Tooltip`, `DropdownMenu`, `ContextMenu`) support standard dismissal via the <kbd>Escape</kbd> key. Pressing Escape closes the outermost active overlay and stops event propagation.

## Focus Management

### Focus Trapping in Modals

Modal surfaces like `Dialog` and `Sheet` automatically constrain keyboard focus within their boundary while open. Tabbing past the last interactive element loops focus back to the first, preventing users from interacting with inactive background content.

### Focus Restoration

When an overlay (such as a Dialog or Popover) closes, Moraine automatically restores focus to the triggering element that opened it. This maintains the user's reading position in assistive technologies and keyboard workflows.

### Initial Auto-Focus

When an overlay opens:

1. Moraine searches for elements with an `autofocus` attribute within the container.
2. If none is found, it focuses the first interactive child (e.g. an input, close button, or menu item).
3. If no interactive child exists, focus moves safely to the container surface itself (`tabindex="-1"`).

## ARIA Attribute Contracts

Moraine manages dynamic ARIA attributes so you don't have to manually wire state strings:

- **State Indication**: Components maintain `aria-expanded="true|false"` on triggers, `aria-selected="true|false"` on selection items, and `aria-checked="true|false|mixed"` on checkboxes.
- **Relationship Wiring**: Triggers and contents are linked via `aria-controls` pointing to deterministic element IDs generated by `useId`.
- **Form Association**: `Field.Label` and `Field.Description` automatically bind `aria-labelledby` and `aria-describedby` to the underlying input control.
- **Validation**: When a field fails validation, Moraine applies `aria-invalid="true"` to the input and connects the error message via `aria-errormessage`.

```tsx
import { Field, Input } from 'moraine'

export function AccountField() {
  return (
    <Field.Root>
      <Field.Label>Email Address</Field.Label>
      {/* Automatically wires id, aria-labelledby, and aria-describedby */}
      <Input type="email" placeholder="name@example.com" />
      <Field.Description>We will never share your email.</Field.Description>
    </Field.Root>
  )
}
```

## Screen Reader Considerations

- **Semantic HTML**: Moraine prefers native HTML elements (`<button>`, `<dialog>`, `<input>`, `<fieldset>`) wherever possible. When using the `as` prop, ensure the delegated element provides equivalent semantic meaning.
- **Visually Hidden Labels**: For icon-only buttons, provide an accessible name using `aria-label`:
  ```tsx
  <Button aria-label="Close settings dialog" variant="ghost">
    <IconClose />
  </Button>
  ```
