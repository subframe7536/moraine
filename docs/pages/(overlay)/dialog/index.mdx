import { Button, Dialog } from '@src'

## Import

```tsx
import { Dialog } from 'moraine'
import type { DialogT } from 'moraine'
```

Use Dialog when an action or form needs focused attention with a labeled modal surface. The trigger and content share disclosure state through the root.

## Anatomy

```text
Dialog (state only; no DOM)
├── trigger (Dialog.Trigger, optional)
├── close (Dialog.Close, optional; placement varies)
├── overlay (optional; portaled while mounted)
└── content (Dialog.Content; portaled while mounted)
    ├── header (Dialog.Header, optional)
    │   ├── title (Dialog.Title, optional)
    │   ├── description (Dialog.Description, optional)
    │   └── action (Dialog.Action, optional)
    ├── contentClose (optional)
    ├── body (Dialog.Body, optional)
    └── footer (Dialog.Footer, optional)
```

The overlay and content are siblings by default. In scrollable overlay mode, content is nested inside the overlay.

Use Content `title` and `description` for simple cases:

```tsx
<Dialog>
  <Dialog.Content title="Settings" description="Update your account.">
    <Dialog.Body>...</Dialog.Body>
    <Dialog.Footer>...</Dialog.Footer>
  </Dialog.Content>
</Dialog>
```

For a custom header layout, compose the anatomy parts:

```tsx
<Dialog.Content>
  <Dialog.Header>
    <Dialog.Title>Settings</Dialog.Title>
    <Dialog.Description>Update your account.</Dialog.Description>
    <Dialog.Action>...</Dialog.Action>
  </Dialog.Header>
  <Dialog.Body>...</Dialog.Body>
  <Dialog.Footer>...</Dialog.Footer>
</Dialog.Content>
```

Explicit `Dialog.Header` replaces the header generated by Content `title` and `description`. `Dialog.Title` and `Dialog.Description` register their actual IDs for the surface's ARIA relationships. Without a title, supply root `ariaLabel` or native ARIA attributes on Content. Configure the overlay, scrolling, fullscreen layout, focus trap, and automatic close button on the root. `Dialog.Action` is the header-side action region; `contentClose` is the automatic corner close rendered by Content. `Dialog.Close` is a separate close control you can place anywhere inside the root.

Use root `portalMount` to place Content in a chosen container when there is no Trigger, or to override the Trigger's document body.

Set `class` or `style` directly on each part. Root `classes` and `styles` provide family-wide slot defaults; Content `classes` and `styles` configure only `overlay`, `content`, and `contentClose`. See [Styling](/styling/customization#style-overrides).

## Usage

### Nested overlays

Nested roots keep dismissal and focus restoration local to the active layer. Escape closes the topmost dialog or popover, then returns focus to its trigger inside the parent dialog.

<Preview path="./nested-overlays" />

### State and dismissal

Use controlled `open` with `onOpenChange` when the surrounding flow owns visibility. `dismissible={false}` blocks outside and Escape dismissal and calls `onClosePrevent`; provide a clear explicit close path in that case.

<Preview path="./state-dismissal" />

### Structure and lifecycle

Set `title` and `description` on Dialog.Content so it receives an accessible name and description. Root `scrollable` and `fullscreen` change the content structure, while `onExitComplete` runs only after the exit presence motion finishes.

<Preview path="./structure-lifecycle" />

### Keyboard interaction

| Key                    | Description                                                        |
| ---------------------- | ------------------------------------------------------------------ |
| <kbd>Escape</kbd>      | Requests dismissal when `dismissible={true}`.                      |
| <kbd>Tab</kbd>         | Moves focus forward through focusable controls inside the dialog.  |
| <kbd>Shift + Tab</kbd> | Moves focus backward through focusable controls inside the dialog. |
