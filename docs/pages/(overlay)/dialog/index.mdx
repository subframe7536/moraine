## Import

```tsx
import { Dialog } from 'moraine'
import type { DialogT } from 'moraine'
```

Use Dialog when an action or form needs focused attention with a labeled modal surface. The trigger and content share disclosure state through the root.

## Anatomy

`Dialog` owns state and family presentation without adding a DOM element. Root `classes` and `styles` provide defaults for this Dialog instance. `Dialog.Trigger` owns its attributes, events, ref, and direct styling; `Dialog.Content` owns the floating surface and its scoped presentation props. Content children fill the body unless an explicit `body` prop is provided.

```text
Root (context only)
├── Trigger
├── overlay
└── content
    ├── header (optional)
    │   ├── title
    │   └── description
    ├── contentClose (optional)
    ├── body
    └── footer
```

- `trigger`: Element that opens the dialog.
- `overlay`: Optional backdrop.
- `content`: Modal surface.
- `header` / `body` / `footer`: Structured content regions.
- `contentClose`: Content-owned convenience close affordance.

`Dialog.Close` is a behavior primitive that closes the nearest Dialog or Modal. It accepts its own `class` and `style`, but does not own a Dialog family slot or receive the automatic corner-close recipe. With `close={true}`, `Dialog.Content` renders `contentClose` even when `header` supplies custom content; the custom header replaces only the default title and description contents.

Dialog and Sheet intentionally share structured slot vocabulary, but retain separate recipes, Theme keys, and visual layouts.

## Usage

### Nested overlays

Nested roots keep dismissal and focus restoration local to the active layer. Escape closes the topmost dialog or popover, then returns focus to its trigger inside the parent dialog.

<Preview path="./nested-overlays" />

### State and dismissal

Use controlled `open` with `onOpenChange` when the surrounding flow owns visibility. `dismissible={false}` blocks outside and Escape dismissal and calls `onClosePrevent`; provide a clear explicit close path in that case.

<Preview path="./state-dismissal" />

### Structure and lifecycle

Use title and description so the dialog receives an accessible name and description. `scrollable` and `fullscreen` change the content structure, while `onExitComplete` runs only after the exit presence motion finishes.

<Preview path="./structure-lifecycle" />

### Keyboard interaction

| Key                    | Description                                                        |
| ---------------------- | ------------------------------------------------------------------ |
| <kbd>Escape</kbd>      | Requests dismissal when `dismissible={true}`.                      |
| <kbd>Tab</kbd>         | Moves focus forward through focusable controls inside the dialog.  |
| <kbd>Shift + Tab</kbd> | Moves focus backward through focusable controls inside the dialog. |
