## Import

```tsx
import { MultiSelect } from 'moraine'
import type { MultiSelectT } from 'moraine'
```

## Features

- **Collection-backed values**: Every committed value resolves through a canonical `TItem` source.
- **Stable tag field**: One input owns focus, keyboard behavior, query, and combobox ARIA.
- **Optional search and creation**: `search` filters; `createItem` explicitly constructs a `TItem`.
- **Separate limits**: `maxCount` limits values; `maxTagCount` only changes presentation.

## Anatomy

```text
control
├── leading (optional)
├── tagsContainer
│   ├── tag
│   │   ├── tagLabel
│   │   └── tagRemove
│   ├── tagOverflow (optional)
│   └── input
├── clear (optional)
└── trigger
```

The trailing trigger is always a real secondary button and is never replaced by clear or loading.
Normal control clicks are open-only. Set `openOnControlClick={false}` to require the trailing button
for pointer opening; typing and Arrow keys still open normally.

## Usage

### Values and search

<Preview path="./values-and-search" />

Without `search`, the single physical input is read-only and printable keys use collection
typeahead. `search` makes it editable and filters the collection. Query state stays separate from
the committed `TItem['value'][]`.

### Create collection items

<Preview path="./create-new-tags" />

Providing `createItem` implicitly enables the editable search input, even with `search={false}`.
It converts normalized text into a valid `TItem`; MultiSelect then commits `TItem.value`. This is
different from TagsInput, which commits free-form strings directly.
