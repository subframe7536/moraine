import { Icon, Input, InputGroup } from '@src'

## Import

```tsx
import { Input, InputGroup, Textarea } from 'moraine'
import type { InputGroupT } from 'moraine'
```

Use InputGroup when an editable control and its addons should share one visual boundary. The inner input or textarea still owns text entry and its accessible name.

## Anatomy

```text
root (InputGroup)
├── leading (InputGroup.Leading, ×n)
├── Input or Textarea (native control)
├── trailing (InputGroup.Trailing, ×n)
└── frame (internal, aria-hidden)
```

Place zero or more `Leading` parts first, then one `Input` or `Textarea`, then zero or more `Trailing` parts. `orientation` belongs to `InputGroup` and determines whether all parts sit beside or above/below the control. `Leading` and `Trailing` accept `compact` to use denser padding for the part. Child type never changes spacing implicitly; use `compact` explicitly when a `Button`, `Kbd`, or other addon should occupy less surrounding space. Both parts accept ordinary JSX.

The final frame element paints the shared boundary and does not receive focus or control attributes.

## Usage

### Direction and orientation

`Leading` renders at the logical start when horizontal and above the control when vertical. `Trailing` renders at the logical end when horizontal and below the control when vertical. Horizontal positions follow the document's writing direction. Configure the orientation default or styles through `inputGroup.defaults.orientation` and `inputGroup.variants.orientation` in your theme.

<Preview path="./alignment" />

### Compact

Set `compact` on a `Leading` or `Trailing` part to reduce its padding while keeping the same layout role. In horizontal groups it uses smaller inline padding; in vertical groups it uses smaller padding on all sides. This is useful for compact buttons, keyboard shortcuts, inline prefixes or suffixes, and other addons that need less surrounding space.

### Styling and forms

`InputGroup` owns the shared border, background, radius, and focus/invalid frame. Set its `size` and `variant` to style the group. Disabled presentation remains on the native `Input` or `Textarea`, and the native control's `variant` applies when it is outside a group.

Size precedence is the control's explicit size, group size, Field size, then theme defaults. `classes.leading`, `classes.trailing`, and their style equivalents set group-wide presentation; each part's `class` and `style` override it.

Keep `name`, `value`, `onValueChange`, `required`, `disabled`, `readOnly`, and ARIA attributes on the control. InputGroup does not register a form field. Clicking non-interactive group space focuses the native control; buttons and links retain their own focus behavior.
