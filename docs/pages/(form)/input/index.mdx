## Import

```tsx
import { Input } from 'moraine'
import type { InputT } from 'moraine'
```

## Features

- **Visual Variants**: Supports `outline`, `subtle`, `ghost`, and `none` styling modes.
- **Composable Actions**: Use [InputGroup](/input-group) and its Leading and Trailing parts to place icons, loading indicators, text, and buttons around the input.
- **Field Integration**: Inherits field identity and state and applies generated validation/accessibility metadata to the native input.
- **Model Modifiers**: Supports value modifiers such as `trim`, `lazy`, and `number` through `modelModifiers`.

## Anatomy

```text
root (native <input>)
```

`ref`, `class`, `style`, `classes.root`, and `styles.root` target the native input. Put container styling and refs on `InputGroup` when composing supporting content.

## Usage

### Native input behavior

`Input` forwards native input attributes. Use `value` with `onValueChange` for controlled text and `defaultValue` for an initial uncontrolled value. `readOnly` keeps the field focusable without allowing edits; `disabled` removes it from interaction.

<Preview path="./controlled-input" />

### Composed controls

Use `InputGroup.Leading` and `InputGroup.Trailing` for static context such as an icon or unit. Password visibility, clearing, copying, and loading remain application behavior: compose buttons and icons into these parts and provide their labels and handlers.

<Preview path="./composed-controls" />

### Keyboard interaction

`Input` keeps native input keyboard behavior. Moraine does not add a built-in Escape-to-clear or search-submit shortcut.

| Key              | Description                                                              |
| ---------------- | ------------------------------------------------------------------------ |
| <kbd>Tab</kbd>   | Moves focus to the input according to normal document focus order.       |
| <kbd>Enter</kbd> | Participates in native form submission when the surrounding form allows. |
