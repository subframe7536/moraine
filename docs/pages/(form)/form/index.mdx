import * as v from 'valibot'

## Import

```tsx
import { createForm, Form, FormField, Input, Switch } from 'moraine'
import type { FormT } from 'moraine'
```

Define a schema, create a Formisch store with `createForm`, and pass it to `Form`:

```tsx
export function NotificationForm() {
  const form = createForm({
    schema,
    initialInput: { email: '', enabled: false },
  })

  return (
    <Form of={form} onSubmit={(output) => console.log(output)}>
      <FormField name="email" label="Email Address">
        <Input leading="i-lucide:mail" />
      </FormField>
      <FormField name="enabled" label="Enable Notifications">
        <Switch />
      </FormField>
      <Button type="submit">Save Changes</Button>
    </Form>
  )
}
```

  {(props) => {
    const LoginSchema = v.object({
      email: v.pipe(v.string(), v.email('Enter a valid email address.')),

        </FormField>

          <Switch label="Remember me on this device" disabled={props.disabled} />

        <Show when={success()}>
          <p class="text-xs text-primary font-medium text-center">Successfully signed in!</p>

## Features

- **Formisch + Valibot**: `createForm` provides the reactive store and schema validation used by Moraine form controls.
- **Form Context**: `Form` provides its store to nested `FormField` components so controls can bind values, validation metadata, and field events.
- **Submission State**: Formisch manages submission state; Moraine mirrors `of.isSubmitting` as `data-submitting` on the form root for styling or coordination.
- **Nested Paths**: Formisch field names can target nested and array values supported by the store.
- **Native Reset Coordination**: Moraine coordinates native form reset with Formisch so control state returns to the store snapshot.

## Anatomy

```text
root (<form> managed by Formisch)
└── composed fields and controls
```

`Form` does not automatically disable child controls during submission. Use the form store's submission state when your application needs that behavior.

## Keyboard Interactions

`Form` relies on native form and child-control keyboard behavior. For example, Enter can submit from eligible single-line form controls, while Tab follows normal document focus order.
