import { Button, createForm, Input, Select, Switch, Textarea } from '@src'
import { Show, createSignal, createComponent } from 'solid-js'
import * as v from 'valibot'

## Import

```tsx
import { createForm, Input, Button, Switch } from 'moraine'
import type { FormT, FormFieldT } from 'moraine'
```

Define a schema, instantiate the form with `createForm`, and render `<form.Form>` and `<form.Field>`:

```tsx
export function NotificationForm() {
  const form = createForm({
    schema,
    initialInput: { email: '', enabled: false },
  })

  return (
    <form.Form onSubmit={(output) => console.log(output)}>
      <form.Field name="email" label="Email Address">
        <Input leading="i-lucide:mail" />
      </form.Field>
      <form.Field name="enabled" label="Enable Notifications">
        <Switch />
      </form.Field>
      <Button type="submit">Save Changes</Button>
    </form.Form>
  )
}
```

## Features

- **Bound Form Instance**: `createForm` creates a reactive Formisch store and attaches pre-bound `<form.Form>` and `<form.Field>` components.
- **Type-Safe Field Paths**: `<form.Field>` automatically infers its schema and provides autocomplete for flat and nested paths (`['profile', 'email']`) without manual generics.
- **Formisch + Standard Schema**: Integrates reactive validation and input management with Valibot, Zod, or Standard Schema.
- **Automated ARIA & Accessible Feedback**: Automatically links `<label>`, helper description (`aria-describedby`), and error messages (`aria-errormessage`, `role="alert"`) with child controls.
- **Flexible Field Layouts**: Vertical by default, with `orientation="horizontal"` for 1-to-3 grid column layouts.
- **Submission & Reset Coordination**: Tracks `form.isSubmitting`, mirrors `data-submitting` on the root, and handles native reset events.
- **Custom Control Render Prop**: Child render function receives `{ error, invalid, size, disabled, required }`.

## Anatomy

```text
form.Form (<form> root managed by Formisch)
└── form.Field (field layout & ARIA wrapper)
    ├── wrapper (label, required indicator, hint, description)
    │   ├── labelWrapper
    │   │   ├── label (form control label)
    │   │   ├── required (asterisk indicator)
    │   │   └── hint (optional badge/subtext)
    │   └── description (helper text)
    └── container (child controls, help message, error alert)
        ├── {children} (input, select, textarea, etc.)
        ├── help (supplemental help note)
        └── error (validation error message with role="alert")
```

`<form.Form>` does not automatically disable child controls during submission. Use `form.isSubmitting` when your application needs that behavior.

## Usage

### Basic form and submission

Create the form with `createForm`, then render `<form.Form>` and `<form.Field>`. The submit handler receives the validated schema output.

<Preview path="./basic-form" />

### Field labels and messages

Configure `label`, `hint`, `description`, `help`, and `required` indicators on `<form.Field>`. Supported Moraine controls automatically link with helper descriptions and error messages via deterministic ARIA attributes.

<Preview path="./labels-messages" />

### Horizontal layout

Set `orientation="horizontal"` to switch from the default stacked layout to a side-by-side grid arrangement, common in settings panels and administrative consoles.

<Preview path="./horizontal-layout" />

### Nested and array paths

Target nested object and array fields by supplying path tuples (for example, `['profile', 'email']`) to the `name` prop. Path types are fully validated and autocompleted based on your schema.

<Preview path="./nested-path" />

### Submission and loading state

Read `form.isSubmitting` to derive button loading spinners or disabled states while async form submissions are in flight.

<Preview path="./async-submit" />

### Reset and state restoration

Coordinate native reset events with Formisch: clicking a `type="reset"` button restores the initial store input snapshot and clears validation metadata.

<Preview path="./reset" />

### Keyboard interaction

`Form` relies on native form and child-control keyboard behavior. For example, Enter can submit from eligible single-line form controls, while Tab follows normal document focus order.
