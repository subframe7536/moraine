import { BaseSelect, Button } from '@src'
import { For } from 'solid-js'

## Import

```tsx
import { BaseSelect, useSelectState } from 'moraine'
import type { BaseSelectT } from 'moraine'
import { useBaseSelectSearchInput, useSearchValue } from 'moraine/utils'
```

BaseSelect owns array selection, disclosure, highlighted navigation, typeahead, listbox primitives,
and form integration. Collection grouping, filtering, query state, tags, and item creation belong to
the composing control.

<Playground
  controls={[
    { kind: 'switch', prop: 'multiple', label: 'Multiple', defaultValue: false },

          <BaseSelect.Trigger as={Button} variant="outline" class="min-w-52 justify-between">
            {(state) =>
              state.value.length ? `${state.value.length} selected` : 'Select a framework…'
            }
          </BaseSelect.Trigger>
        </BaseSelect.Control>
        <BaseSelect.Content>
          <BaseSelect.Listbox>
            <For each={ITEMS}>
              {(item) => <BaseSelect.Item item={item}>{item.label}</BaseSelect.Item>}
            </For>
          </BaseSelect.Listbox>
        </BaseSelect.Content>
      </BaseSelect>
    )
  }}

## Anatomy

```text
BaseSelect
├── Control
│   └── Trigger
└── Content
    ├── Listbox
    │   ├── Group (optional)
    │   │   ├── GroupLabel
    │   │   └── Item (×n)
    │   └── Separator (optional)
    └── Empty (optional)
```

Control is an optional, non-interactive layout container and floating anchor. It does not toggle,
own keyboard navigation, become a tab stop, or receive `role="combobox"`. Trigger is the primary
select-like focus owner and activator. If Control is omitted, Content falls back to the registered
focus owner for positioning.

### Item fields

`BaseSelect.Item` accepts collection item data via the `item` prop: `<BaseSelect.Item item={item} />`.
Ordinary component props are DOM/rendering props for the rendered `<div>`. Custom item fields are
available through render state: `<BaseSelect.Item<MyItem> item={item}>{(state) => state.item.custom}</BaseSelect.Item>`,
and arbitrary item fields never leak into rendered DOM attributes.

### Canonical vs navigation collections

By default, `<BaseSelect items={items}>` uses `items` as both the canonical data source and the
active navigation collection.

For custom filtered compositions (such as searchable controls), provide `getItemByValue` alongside
a filtered `items` view:

```tsx
<BaseSelect items={filteredItems()} getItemByValue={(value) => allItemsByValue.get(value)}>
  {/* ... */}
</BaseSelect>
```

Here, `items` represents the current navigation view (visible in the popup listbox), while
`getItemByValue` provides authoritative lookup for canonical item data (such as labels, disabled
state, and form serialization) even when items are filtered out of the view.

### Styling

BaseSelect exposes `control`, `trigger`, `content`, `listbox`, `item`, `group`, `groupLabel`,
`separator`, and `empty`. Its root renders no element, so use root `classes` and `styles` for defaults
and direct `class` or `style` on the part that renders the element. See [Styling](/styling/advanced#advanced-style-resolution)
for nested Provider, Portal, and class-merging behavior.
