## Import

Import the component and its companion types from the package root:

```tsx
import { FormField } from 'moraine'
import type { FormFieldT } from 'moraine'
```

When used inside `Form`, a named `FormField` automatically subscribes to schema validation and errors:

```tsx
<FormField<typeof schema> name={['profile', 'email']} label="Email Address">
  <Input placeholder="you@company.com" leading="i-lucide:mail" />
</FormField>
```

## Features

- **Automated ARIA Association**: Automatically links `<label>`, helper description (`aria-describedby`), and error messages (`aria-errormessage`) with the child control using deterministic IDs.
- **Formisch Schema Integration**: Binds nested or flat path names (`['users', 0, 'email']`) with type-safe schema validation.
- **Vertical & Horizontal Layouts**: Switch to `orientation="horizontal"` for 1-to-3 grid columns common in desktop settings and admin consoles.
- **Render Context & Error Reactivity**: Child function render prop receives `{ invalid, error, size, disabled, required }` to dynamically tailor child components.
- **Granular Slots**: Supports separate slots for `label`, `hint`, `description`, `help`, and `error`.

## Anatomy

Hierarchical slot and element structure:

```text
root
├── wrapper (label & description header)
│   ├── labelWrapper
│   │   ├── label (form control label)
│   │   ├── required (asterisk indicator)
│   │   └── hint (optional badge/subtext)
│   └── description (helper text)
└── container (control & feedback area)
    ├── {children} (input, select, textarea, etc.)
    ├── help (supplemental help note)
    └── error (validation error message)
```

- `root`: Field wrapper applying size, invalid state, and layout classes.
- `wrapper`: Top section holding the title, hint, and description.
- `container`: Bottom or right section holding the input control and error feedback.
- `error`: Rendered conditionally when validation errors exist, automatically setting `role="alert"`.

## Usage

### Binding a field

Inside `Form`, give `FormField` a typed `name` to bind a descendant Moraine control to that Formisch path. An unnamed field is useful for layout and explicit accessibility metadata, but does not subscribe to form state.

<Preview path="./field-binding" />

### Labels, messages, and custom controls

`label`, `description`, help text, and errors are associated with supported child controls. Use `error` for application-owned validation messages. A child render function receives live field metadata when a custom control needs to react to invalid, disabled, required, or size state.

<Preview path="./labels-messages" />

### Accessibility

- Automatically injects `id`, `aria-labelledby`, `aria-describedby`, and `aria-invalid` onto supported child controls.
- Renders error messages with `role="alert"` so screen readers immediately announce validation issues.
