`<AlertDialog>` mounts a host with no DOM of its own. Each call opens a dialog whose panel is
`content`, with a `header` for the icon and copy, and a `footer` for the `cancel` and `action`
buttons.

## Usage

Use Alert Dialog for a short confirm, info, warning, error, or success prompt opened from an event
handler. Use [Dialog](/components/dialog) when the task has its own trigger, body, and footer.

Mount `<AlertDialog>` once. It renders no children and holds no open state. A call before the host
is mounted throws. On the server, a call returns a handle whose `result()` is already `'api'`.

Props on the host are live defaults for every dialog, and options passed to a method override them.
Only `undefined` falls back to the host: `false`, `0`, and `null` on a call are kept, so
`closable: false` or `align: null` overrides a host default.

Give each host a unique `id` when more than one is mounted. A call without `hostId` goes to the host
without an id and throws if only hosts with an id are mounted. Pass `hostId` to target
`<AlertDialog id="billing" />`. Unmounting a host settles its open dialogs as `'api'` and removes
them immediately.

```tsx
import { AlertDialog, Button, MoraineProvider } from 'moraine'

export function App() {
  return (
    <MoraineProvider>
      <AlertDialog maxWidth={420} />
      <Button
        onClick={() => {
          void AlertDialog.confirm({
            type: 'error',
            title: 'Delete this project?',
            description: 'This action cannot be undone.',
          })
        }}
      >
        Delete
      </Button>
    </MoraineProvider>
  )
}
```

### Shared model

Alert Dialog and [Toast](/components/toast) use the same options, actions, handle, and close
reasons. Every instance is created with a static method that takes an options object.

```ts
interface Action {
  label?: JSX.Element
  variant?: ButtonT.Variants['variant']
  tone?: ButtonT.Variants['tone']
  leading?: IconT.Name
  disabled?: boolean
  class?: SlotClassValue
  style?: SlotStyleValue
  onClick?: (event?: MouseEvent) => void | Promise<unknown>
}

type CloseReason = 'action' | 'cancel' | 'dismiss' | 'timeout' | 'api'

interface Handle {
  id: string | number
  update: (options: UpdateOptions) => void
  close: () => void
  result: () => Promise<CloseReason>
}
```

`action.onClick` and `cancel.onClick` run before the instance closes. A returned promise shows
loading on that button and disables the other one. While that promise is pending, a dialog blocks
Escape, the overlay, and the corner close button, and a toast pauses its timer.

Calling `event.preventDefault()`, rejecting, or throwing leaves the instance open. A throw or
rejection is reported with `console.error`. Otherwise the instance closes with `'action'` or
`'cancel'`.

- `handle.close()` and `close(id)` close with `'api'`.
- Escape, the overlay, the corner close button, and a toast swipe close with `'dismiss'` and do not
  run the cancel handler.
- A toast timer closes with `'timeout'`.

`result()` resolves once with that reason, and calling it again returns the same promise. The handle
itself is not a promise.

```tsx
const handle = AlertDialog.confirm({ title: 'Delete this project?', type: 'error' })
if ((await handle.result()) === 'action') {
  deleteProject()
}
```

`update` merges the next options into an open instance; options set to `undefined` are ignored, and
an update after close does not reopen it. `update` replaces `action` and `cancel` as a whole, so
include `onClick` again when the label changes.

Reusing an open `id` with the same method and render updates that instance in place. With a
different method or render, the open dialog closes with `'api'` and a new one opens.

Custom content has two entry points:

- `AlertDialog.custom(render, options?)`: supplies a render for that call, either a static
  `JSX.Element` or a `Component<DialogRenderProps>`.
- `<AlertDialog dialogRender={render} />`: supplies a reusable render for every other call on that
  host. It must be a `Component<DialogRenderProps>` because the host creates a fresh instance for
  each dialog.

A `.custom()` render wins over the host `dialogRender`, which wins over the built-in layout. The
render receives `id`, the resolved `options`, `pending()`, `action()`, `cancel()`, `close()`,
`update()`, `titleId`, and `descriptionId`. It replaces the inner content while the dialog keeps its
overlay, focus trap, `role="alertdialog"`, and panel width.

### Methods

`show`, `info`, `warning`, `error`, and `success` show the action button only. `confirm` shows
cancel as well. Set `cancel: true` to use the locale label, `cancel: { label }` to change it, or
`cancel: false` to hide it on a confirm.

`info`, `success`, `warning`, and `error` set `type`, which picks the leading icon and its color;
`icon` replaces the icon. The action button keeps its neutral tone, so pass
`action: { tone: 'danger' }` for a destructive action.

`close()` closes every open dialog, `close(id)` closes one, `close({ hostId })` closes every dialog
on that host, and `close({ hostId, id })` closes one dialog there. All settle with `'api'` before
the exit transition finishes. Unmounting a host also closes its dialogs with `'api'` and calls
`onClose`.

`AlertDialog.update(id, options)` updates the open dialog with that id on any host, matching
`handle.update`.

```ts
AlertDialog.show(options)
AlertDialog.confirm(options)
AlertDialog.info(options)
AlertDialog.success(options)
AlertDialog.warning(options)
AlertDialog.error(options)
AlertDialog.custom(render, options?)
AlertDialog.update(id, options)
AlertDialog.close(id?)
AlertDialog.close({ hostId?, id? })
```

### Defaults

Action and cancel labels use the `dialog` message group (`ok`, `cancel`) when `label` is omitted.
Set `translations` on the host or a call to change these labels and the corner button's `close`
label. `closable` shows the corner close button and defaults to `false`.

`title` names the dialog. Only `custom` calls may omit it; they name the dialog with `ariaLabel`, or
by putting `titleId` on the custom heading so `aria-labelledby` points at it.

### Layout

`variant="subtle"` gives the footer a top border and muted background. `align="center"` stacks the
icon, title, and description and stretches the actions into an equal row. Both are props of the host
and options of a call.

```tsx
AlertDialog.confirm({
  title: 'Allow accessory to connect?',
  description: 'Do you want to allow the USB accessory to connect to this device?',
  icon: 'i-lucide:bluetooth',
  align: 'center',
  variant: 'subtle',
  action: { label: 'Allow' },
  cancel: { label: "Don't allow" },
})
```

### Dismissal

A pointer press on the overlay dismisses the dialog when `closeOnOutsideClick` is `true` (default
`false`). Escape dismisses it unless `closeOnEscape` is `false` (default `true`). The corner close
button appears when `closable` is `true`. Escape closes only the topmost dialog. All three settle
with `'dismiss'`.

`transition` on the host sets the default for every dialog on it, and the same option in a call
overrides it. `transition: false` unmounts a closed dialog without its exit animation.

### Custom content

`custom` is for a layout the built-in title, description, and actions cannot express. Call
`props.action()` and `props.cancel()` so loading, dismissal, and `result()` stay shared with the
default buttons.

```tsx
AlertDialog.custom(
  (props) => {
    const [name, setName] = createSignal('')
    return (
      <>
        <h2 id={props.titleId}>{props.options.title}</h2>
        <Input value={name()} onValueChange={setName} />
        <Button variant="outline" onClick={(event) => void props.cancel(event)}>
          Cancel
        </Button>
        <Button
          tone="danger"
          disabled={name() !== 'moraine'}
          autoLoading
          onClick={(event) => props.action(event)}
        >
          Delete
        </Button>
      </>
    )
  },
  { title: 'Delete repository?', action: { onClick: deleteRepo } },
)
```
