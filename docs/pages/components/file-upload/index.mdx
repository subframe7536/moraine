## Usage

Use FileUpload to collect local files before the application sends them. Selection and validation
happen in the component; upload transport belongs to the caller.

```tsx
import { FileUpload } from 'moraine'

export function Example() {
  return <FileUpload label="Upload files" />
}
```

### Selecting files

`variant` sets the appearance: `area` (the default) shows a large dashed drop area, and `button`
shows a compact picker button. Clicking anywhere in the visible control, including its padding, icon,
and text, opens the file picker. `dropzone` (default `true`) only controls whether files can be
dropped onto the control; it does not change how the control looks. File previews and removal
actions are outside the picker hit area.

Use `multiple` when the value can hold more than one `File`. New files are appended to the
selection, and `value` and `onValueChange` use a `File[]`. Without `multiple`, a new file replaces
the current one, and the value is `File | null`.

```tsx
<FileUpload multiple label="Click anywhere or drop files" description="Choose documents and images." />
<FileUpload variant="button" label="Attach files" />
```

### File list

The selected files appear in a list below the control, with an image thumbnail for image files and
`fileIcon` for other types. Set `fileList={false}` to omit the list and render the selection
yourself from `onValueChange`. Use `itemRender` to replace each entry. It receives `file`, `index`,
`previewUrl`, `remove`, and `disabled`, and must return an `<li>`.

```tsx
<FileUpload
  multiple
  itemRender={(item) => (
    <li>
      {item.file.name}
      <button type="button" disabled={item.disabled} onClick={item.remove}>
        Remove
      </button>
    </li>
  )}
/>
```

### Rejections and forms

`accept`, `minSize`, `maxSize`, and `maxFiles` validate each picked or dropped file before it is
added. `maxFiles` counts files already selected and applies only with `multiple`. Rejected files are
reported to `onValueInvalid` as `rejections`, each with the file and its `reasons`, named after the
matching `ValidityState` key: `typeMismatch` (not in `accept`), `rangeUnderflow` (under `minSize`),
`rangeOverflow` (over `maxSize`), `tooLong` (over `maxFiles`), and `duplicate` (already selected).
Accepted files from the same batch are still added.

`readOnly` keeps the selected list visible but blocks adding and removing files. `disabled` removes
all interaction. Both inherit the enclosing Field's state when omitted, and an explicit `false`
overrides it.

```tsx
<FileUpload
  multiple
  accept="image/png,image/jpeg"
  maxFiles={2}
  maxSize={1024 * 1024}
  onValueInvalid={({ rejections }) => setRejections(rejections)}
/>
<FileUpload disabled label="Disabled upload" />
<FileUpload readOnly label="Read-only upload" />
```

### Keyboard interaction

| Key                                 | Description                                                                              |
| ----------------------------------- | ---------------------------------------------------------------------------------------- |
| <kbd>Enter</kbd> / <kbd>Space</kbd> | Opens the native operating system file picker dialog when the upload control is focused. |
| <kbd>Tab</kbd>                      | Navigates between the upload control and individual file removal buttons.                |
