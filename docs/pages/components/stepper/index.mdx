## Usage

Use Stepper to show progress through a fixed sequence of steps. Decide how far users may jump ahead
with `navigation`. Use [Tabs](/components/tabs) for peer panels that are not a
sequence. Use [Pagination](/components/pagination) for a result set with a known page count.

```tsx
import { Stepper } from 'moraine'

export function Example() {
  return (
    <Stepper
      items={[
        { value: 'details', label: 'Details' },
        { value: 'review', label: 'Review' },
      ]}
    />
  )
}
```

### Navigation modes

`navigation` (default `'none'`) controls which steps users can activate from their triggers:

- `none` enables only the active step, so the flow moves through your own controls.
- `linear` enables completed steps and the next step, so later steps stay locked until earlier ones
  are reached.
- `free` enables every enabled step.

`onValueChange` fires only when the user activates a different step from a trigger, so in practice
only in `linear` and `free`. It does not fire for programmatic `value` changes. To drive the flow
from your own Previous and Next buttons, control `value` and update it in those handlers. Set
`disabled` on the Stepper to block every trigger.

```tsx
<Stepper items={STEPS} value={step()} onValueChange={setStep} navigation="linear" />
```

### Panels and orientation

Step triggers and panels use tab semantics (`tablist`, `tab`, `tabpanel`). Every item requires a
unique `value`; an item that repeats an earlier value renders disabled and logs a development
warning. `item.content` is static JSX or a component that receives `{ value, index }`; only the
active step's panel renders, and a step without `content` has no panel. Vertical orientation changes
the layout and the arrow keys that move between steps. Stepper marks every step before the active
one as completed, based on item order. Set `item.icon` to replace the step number in the indicator.

```tsx
<Stepper
  defaultValue="details"
  orientation="vertical"
  items={[
    { value: 'details', label: 'Project details', content: () => <ProjectForm /> },
    { value: 'target', label: 'Deploy target', content: () => <TargetForm /> },
  ]}
/>
```

### Keyboard interaction

`activationMode` controls whether arrow-key focus activates a step immediately (`automatic`, the
default) or only moves focus until <kbd>Enter</kbd> or <kbd>Space</kbd> confirms it (`manual`).
Disabled and navigation-locked steps are skipped. Navigation stops at the first and last step unless
you set `loop`.

| Key                                          | Description                                                           |
| -------------------------------------------- | --------------------------------------------------------------------- |
| <kbd>ArrowRight</kbd> / <kbd>ArrowLeft</kbd> | Moves to the next or previous enabled step in horizontal orientation. |
| <kbd>ArrowDown</kbd> / <kbd>ArrowUp</kbd>    | Moves to the next or previous enabled step in vertical orientation.   |
| <kbd>Home</kbd> / <kbd>End</kbd>             | Moves to the first or last enabled step.                              |
| <kbd>Enter</kbd> / <kbd>Space</kbd>          | Activates the focused step in manual activation mode.                 |
