## Usage

Use Collapsible for one disclosure whose trigger and content belong to the surrounding layout. Use
[Accordion](/components/accordion) when several disclosures share selection rules.

```tsx
import { Collapsible } from 'moraine'

export function Example() {
  return (
    <Collapsible>
      <Collapsible.Trigger>Details</Collapsible.Trigger>
      <Collapsible.Content>More information</Collapsible.Content>
    </Collapsible>
  )
}
```

### Controlled state

Use `open` with `onOpenChange` for controlled state, or `defaultOpen` when the component owns its
initial state. `onOpenChange` receives the next state when the user toggles a trigger, and does not
fire when you change `open` yourself. With a controlled `open`, the state changes only when you
update it. The trigger and content parts can sit anywhere inside the root, so you can compose them
into a custom layout.

`disabled` on `Collapsible` blocks every trigger and keeps the current open state. `disabled` on
`Collapsible.Trigger` blocks only that trigger. Set `transition` to animate the content height. The
content then stays mounted until the closing animation finishes, and the measured height is exposed
as `--mo-collapsible-content-height` on the root. Animation is skipped for `prefers-reduced-motion`.

```tsx
<Collapsible open={open()} onOpenChange={setOpen}>
  <Collapsible.Trigger>Advanced settings</Collapsible.Trigger>
  <Collapsible.Content>Telemetry endpoints</Collapsible.Content>
</Collapsible>
```

### Content lifetime

The content shell stays mounted so the trigger's `aria-controls` points to a real element even while
closed. `forceMount` controls the content inside it. By default, content mounts on first open and
unmounts after it closes. Set `forceMount` when content holds state that should survive closing; it
mounts the content even before the first open. Mounted closed content stays hidden and `inert`, and
browser find-in-page can reveal it, which opens the Collapsible and calls `onOpenChange`.

```tsx
<Collapsible forceMount defaultOpen>
  <Collapsible.Trigger>Filters</Collapsible.Trigger>
  <Collapsible.Content>
    <Input defaultValue="tag:moraine" />
  </Collapsible.Content>
</Collapsible>
```

### Styling

Configure `root`, `trigger`, and `content` through `collapsible.base` in your Theme. The root and
Content expose `data-expanded` and `data-closed` for state styling, and the Trigger also exposes
`data-disabled`. Collapsible also renders an internal wrapper with `data-expanded`, `data-closed`,
and `data-transition` for measurement, height animation, presence, and accessibility. You cannot
configure that wrapper through Theme, `classes`, `styles`, or Content props.

Root `classes` and `styles` set defaults for this Collapsible. Use `class` and `style` directly on
the root, Trigger, or Content to style those elements. Content's `ref` and `as` apply to the inner
Content element. There are no visual variants.

```tsx
<Collapsible classes={{ trigger: 'font-medium', content: 'text-sm text-muted-foreground' }}>
  <Collapsible.Trigger>Details</Collapsible.Trigger>
  <Collapsible.Content>More information</Collapsible.Content>
</Collapsible>
```

### Keyboard interaction

The trigger renders a `button` by default, or an `a` when you pass `href`. Pass `as` to render a
different element or component, which then follows its own keyboard semantics.
