Portal owns the mounted Overlay and Content subtree and preserves it through exit motion.

## Usage

Use Modal when you compose trigger, backdrop, and content yourself. Use [Dialog](/components/dialog)
for a structured title, description, body, and footer. Use [Sheet](/components/sheet) for a drawer
from a viewport edge. Use [Popover](/components/popover) for anchored interactive content.
[Dialog](/components/dialog) and [Sheet](/components/sheet) wrap this primitive; their Content
parts include a Portal internally.

```tsx
import { Button, Modal } from 'moraine'

export function Example() {
  return (
    <Modal>
      <Modal.Trigger as={Button}>Open</Modal.Trigger>
      <Modal.Portal>
        <Modal.Overlay />
        <Modal.Content ariaLabel="Details">
          Modal content
          <Modal.Close as={Button}>Close</Modal.Close>
        </Modal.Content>
      </Modal.Portal>
    </Modal>
  )
}
```

### Composition

Place `Modal.Overlay` and `Modal.Content` inside the same `Modal.Portal`. The Portal mounts them
when open and keeps them present through exit animations. Without it, both parts render in place
and your application controls their mounting. One root owns one active Content; use a nested
Modal root for a second surface.

```tsx
<Modal>
  <Modal.Trigger as={Button}>Open</Modal.Trigger>
  <Modal.Portal>
    <Modal.Overlay />
    <Modal.Content ariaLabel="Custom surface">
      {(context) => (
        <div>
          Custom surface
          <Button onClick={context.close}>Close</Button>
        </div>
      )}
    </Modal.Content>
  </Modal.Portal>
</Modal>
```

`Modal.Content` children may be JSX or a function that receives close helpers. Provide an accessible
name with `ariaLabel` or `ariaLabelledBy` on `Modal.Content`.

### Focus and outside interaction

`modal` defaults to `true`: focus stays inside the surface, outside content is hidden from assistive
technology, and native outside pointer actions are prevented.

Setting `modal={false}` allows focus to leave, but Escape and outside interactions still request
closure according to `dismissible`. Scroll locking is independent: `preventScroll` defaults to
`true`. To allow background page interaction, set `preventScroll={false}` and omit `Modal.Overlay`.

### Styling and portal placement

The root renders no element. Apply `class` and object `style` to rendered parts; root `classes`
and `styles` set their slot defaults. See [Customization](/docs/customization#the-4-layer-override-hierarchy).

Set root `portalMount` for a chosen container, including controlled surfaces without a Trigger.
`Modal.Portal mount` overrides that default.

### State and exit lifecycle

Use `open` with `onOpenChange` for controlled visibility. `onExitComplete` waits for the overlay
and content exit animations to finish. An empty `class` does not disable built-in styles.

```tsx
<Modal open={open()} onOpenChange={setOpen} onExitComplete={() => setLog('Exit complete')}>
  <Modal.Portal>
    <Modal.Overlay />
    <Modal.Content ariaLabel="Lifecycle">
      {(context) => <Button onClick={context.close}>Dismiss</Button>}
    </Modal.Content>
  </Modal.Portal>
</Modal>
```

### Keyboard interaction

| Key                    | Description                                        |
| ---------------------- | -------------------------------------------------- |
| <kbd>Escape</kbd>      | Requests dismissal when `dismissible={true}`.      |
| <kbd>Tab</kbd>         | Moves focus forward within the modal focus scope.  |
| <kbd>Shift + Tab</kbd> | Moves focus backward within the modal focus scope. |
