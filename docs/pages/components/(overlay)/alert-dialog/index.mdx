## Usage

Use Alert Dialog for a short confirm, info, warning, error, or success prompt opened from an event
handler. Use [Dialog](/components/dialog) when the task has its own trigger, body, and footer.

Mount `<AlertDialog>` once, inside `MoraineProvider`. It renders no children. Props on that host
are defaults for every dialog opened while it is mounted, and options passed to a method override
them. Call `AlertDialog` before the host is mounted and the call throws. On the server the same
calls return a promise that is already settled as `false` and do not require a host.

Give each host a unique `id` when more than one is mounted. If multiple hosts share an id, calls
targeting that id resolve to the last mounted host. A call without an id uses the last mounted host.
Pass the id in options (`{ id: 'custom' }`) to target one host. Unmounting a host settles its open dialogs as
`false` and removes them immediately.

```tsx
import { AlertDialog, Button, MoraineProvider } from 'moraine'

export function App() {
  return (
    <MoraineProvider>
      <AlertDialog okText="Continue" cancelText="Back" width={420} />
      <Button
        onClick={() => {
          void AlertDialog.confirm({
            title: 'Delete this project?',
            description: 'This action cannot be undone.',
            danger: true,
          })
        }}
      >
        Delete
      </Button>
    </MoraineProvider>
  )
}
```

### Methods

`confirm` resolves `true` from OK and `false` from cancel, Escape, the corner close button, or
`close` / `destroy`. `confirm` includes a cancel action. `info`, `warning`, `error`, and `success`
show the OK action only, unless `cancel` is set.

`onOk` and `onCancel` run before the dialog closes. A rejected promise or a synchronous throw leaves
the dialog open. A synchronous throw is reported with `console.error` and does not show loading. A
rejection is reported with `console.error`, rethrown to the action button, and shows loading while
the promise is pending. While one action is pending, the other action is disabled and Escape does
not dismiss the dialog. `close`, `destroy`, and `destroyAll` resolve `false` without calling those
handlers, including while an action is pending. `destroy` removes the dialog immediately. `close`
plays the exit transition and resolves `false` before that transition finishes. `update` merges the
next options into the open dialog. Calling `update` after `close` does not reopen it.

```ts
const AlertDialog: {
  confirm: (options: AlertDialogT.Options) => AlertDialogT.Instance
  info: (options: AlertDialogT.Options) => AlertDialogT.Instance
  warning: (options: AlertDialogT.Options) => AlertDialogT.Instance
  error: (options: AlertDialogT.Options) => AlertDialogT.Instance
  success: (options: AlertDialogT.Options) => AlertDialogT.Instance
  destroyAll: (id?: string) => void
}

namespace AlertDialogT {
  interface Instance extends Promise<boolean> {
    close: () => void
    destroy: () => void
    update: (options: AlertDialogT.UpdateOptions) => void
  }
}
```

### Defaults

Host props are read when a dialog opens. Changing them later does not update a dialog that is
already open. Omitted host props do not replace a call option. `false`, `0`, and `null` on the
call are kept: `icon: null` still omits the icon when the host sets one.

OK and Cancel labels use the `dialog` message group (`ok`, `cancel`) when `okText` and
`cancelText` are omitted. `ariaLabel` names the dialog when `title` is omitted.

### Layout

`subtle` gives the footer a top border and muted background, like Card's subtle variant. `center`
stacks the icon, title, and description and stretches the actions into an equal row.

```tsx
AlertDialog.confirm({
  title: 'Allow accessory to connect?',
  description: 'Do you want to allow the USB accessory to connect to this device?',
  icon: 'i-lucide-bluetooth',
  center: true,
  subtle: true,
  okText: 'Allow',
  cancelText: "Don't allow",
})
```

### Dismissal

An outside pointer press does not dismiss the dialog unless `closeOnOverlayClick` is set. Escape
dismisses it unless `closeOnEscape` is `false`. The corner close button stays hidden unless `close`
is set. Escape closes only the topmost alert dialog.
