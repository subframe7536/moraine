`<AlertDialog>` mounts a host with no DOM of its own. Each call opens a dialog whose panel is
`content`, with a `header` for the icon and copy, and a `footer` for the action buttons.

## Usage

Use Alert Dialog for a short confirm, info, warning, error, or success prompt opened from an event
handler. Use [Dialog](/components/dialog) when the task has its own trigger, body, and footer.

Mount `<AlertDialog>` once. It renders no children and holds no open state. Props on that host are
live defaults for every dialog, and options passed to a method override them. `false`, `0`, and
`null` on the call are kept: `icon: null` still omits the icon when the host sets one. A call
before the host is mounted throws. On the server the same call returns a handle whose `result()`
is already `'api'`.

Give each host a unique `id` when more than one is mounted. A call without `host` goes to the host
without an id and throws if only hosts with an id are mounted. Pass `host` to target `<AlertDialog id="billing" />`. Unmounting a host settles its
open dialogs as `'api'` and removes them immediately.

```tsx
import { AlertDialog, Button, MoraineProvider } from 'moraine'

export function App() {
  return (
    <MoraineProvider>
      <AlertDialog width={420} />
      <Button
        onClick={() => {
          void AlertDialog.confirm({
            title: 'Delete this project?',
            description: 'This action cannot be undone.',
            danger: true,
          })
        }}
      >
        Delete
      </Button>
    </MoraineProvider>
  )
}
```

### Shared model

Alert Dialog and [Toast](/components/toast) use the same options, actions, handle, and close
reasons. Every instance is created with a static method that takes an options object.

```ts
interface Action {
  label?: JSX.Element
  variant?: ButtonT.Variant['variant']
  leading?: IconT.Name
  disabled?: boolean
  onClick?: (event?: MouseEvent) => void | Promise<unknown>
}

type CloseReason = 'action' | 'cancel' | 'dismiss' | 'timeout' | 'api'

interface Handle {
  id: string | number
  update: (options: UpdateOptions) => void
  close: () => void
  result: () => Promise<CloseReason>
}
```

`action.onClick` and `cancel.onClick` run before the instance closes. A returned promise shows
loading on that button and disables the other one. A dialog also blocks Escape, the overlay, and
the corner close button while that promise is pending. A toast pauses its timer. Calling
`event.preventDefault()`, rejecting, or throwing leaves the instance open. A throw or rejection is
reported with `console.error`. Otherwise the instance closes with `'action'` or `'cancel'`.

`handle.close()` and `close(id)` close with `'api'`. Escape, the overlay, the corner close button,
and a toast swipe close with `'dismiss'` and do not run the cancel handler. A toast timer closes
with `'timeout'`. `result()` resolves once with that reason, and calling it again returns the same
promise. The handle itself is not a promise.

```tsx
const handle = AlertDialog.confirm({ title: 'Delete this project?', danger: true })
if ((await handle.result()) === 'action') {
  deleteProject()
}
```

`update` merges the next options into an open instance. An update after close does not reopen it.
Reusing an open `id` with the same method and render updates that instance in place. With a different method or render, the open dialog closes with `'api'` and a new one opens. `update` replaces `action` and `cancel` as a
whole, so include `onClick` again when the label changes.

Custom content has two entry points. `AlertDialog.custom(render, options?)` supplies a render for
that call. `<AlertDialog dialogRender={render} />` supplies one for every other call on that host.
A `.custom()` render wins, then the host render, then the built-in layout. The render receives the
id, the resolved options, `pending()`, `action()`, `cancel()`, `close()`, `update()`, `titleId`,
and `descriptionId`. It replaces the inner content. The dialog keeps its overlay, focus trap,
`role="alertdialog"`, and panel width.

### Methods

`show`, `info`, `warning`, `error`, and `success` show the action button only. `confirm` shows
cancel as well. Set `cancel: true` to use the locale label, `cancel: { label }` to change it, or
`cancel: false` to hide it on a confirm. With `danger` and the default type, confirm uses the
caution icon and a danger action.

`close()` closes every open dialog. `close(id)` closes one. `close({ host })` closes every dialog on
that host, and `close({ host, id })` closes one dialog there. All settle with `'api'` before the exit
transition finishes. Unmounting a host also closes its dialogs with `'api'` and calls `onClose`.

```ts
AlertDialog.show(options)
AlertDialog.confirm(options)
AlertDialog.info(options)
AlertDialog.success(options)
AlertDialog.warning(options)
AlertDialog.error(options)
AlertDialog.custom(render, options?)
AlertDialog.update(id, options)
AlertDialog.close(id?)
AlertDialog.close({ host?, id? })
```

### Defaults

Action and cancel labels use the `dialog` message group (`ok`, `cancel`) when `label` is omitted.
The corner button uses `close`. `aria-label` names the dialog when `title` is omitted. With a custom
render, put `titleId` on the heading so `aria-labelledby` can point at it, or pass `ariaLabel`.

### Layout

`subtle` gives the footer a top border and muted background. `center` stacks the icon, title, and
description and stretches the actions into an equal row.

```tsx
AlertDialog.confirm({
  title: 'Allow accessory to connect?',
  description: 'Do you want to allow the USB accessory to connect to this device?',
  icon: 'i-lucide-bluetooth',
  center: true,
  subtle: true,
  action: { label: 'Allow' },
  cancel: { label: "Don't allow" },
})
```

### Dismissal

An outside pointer press dismisses the dialog when `closeOnOverlayClick` is set. Escape dismisses
it when `closeOnEscape` is left on, which is the default. The corner close button is shown when
`close` is set. Escape closes only the topmost alert dialog. All three settle with `'dismiss'`.

### Custom content

`custom` is for a layout the built-in title, description, and actions cannot express. Call
`props.action()` and `props.cancel()` so loading, dismissal, and `result()` stay shared with the
default buttons.

```tsx
AlertDialog.custom(
  (props) => {
    const [name, setName] = createSignal('')
    return (
      <>
        <h2 id={props.titleId}>{props.options.title}</h2>
        <Input value={name()} onValueChange={setName} />
        <Button variant="outline" onClick={(event) => void props.cancel(event)}>
          Cancel
        </Button>
        <Button
          variant="danger"
          disabled={name() !== 'moraine'}
          loadingAuto
          onClick={(event) => props.action(event)}
        >
          Delete
        </Button>
      </>
    )
  },
  { title: 'Delete repository?', danger: true, action: { onClick: deleteRepo } },
)
```
