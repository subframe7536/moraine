Place Leading parts before one Input or Textarea, then Trailing parts. The final frame element paints the shared boundary.

## Usage

Use InputGroup when an editable control and its addons share one visual boundary. Render a single [Input](/components/input) or [Textarea](/components/textarea) as a direct child; the control still owns text entry and its accessible name.

`InputGroup.Leading` and `InputGroup.Trailing` must render inside an `InputGroup`, and each renders a `div` unless `as` is set.

```tsx
import { Field, Input, InputGroup } from 'moraine'

export function Example() {
  return (
    <Field label="Username">
      <InputGroup>
        <InputGroup.Leading>@</InputGroup.Leading>
        <Input placeholder="username" />
      </InputGroup>
    </Field>
  )
}
```

### Direction and orientation

In horizontal groups (the default), `Leading` and `Trailing` follow the document writing direction. In vertical groups, they sit above and below the control.

Configure `inputGroup.defaultVariants.orientation` in your Theme to change the shared default, or `inputGroup.variants.orientation` to override its styles.

```tsx
<InputGroup>
  <InputGroup.Leading>https://</InputGroup.Leading>
  <Input aria-label="Website" placeholder="example.com" />
  <InputGroup.Trailing>.com</InputGroup.Trailing>
</InputGroup>
<InputGroup orientation="vertical">
  <InputGroup.Leading>Project website</InputGroup.Leading>
  <Input aria-label="Website details" />
  <InputGroup.Trailing>Use your public domain.</InputGroup.Trailing>
</InputGroup>
```

### Compact

Set `compact` on `Leading` or `Trailing` to reduce its padding (inline padding in horizontal groups, all sides in vertical groups). Use it for icon buttons, keyboard shortcuts, and inline prefixes.

```tsx
<InputGroup>
  <InputGroup.Leading>https://</InputGroup.Leading>
  <Input aria-label="Website" placeholder="example.com" />
  <InputGroup.Trailing compact>
    <Button size="icon-sm" variant="ghost" leading="i-lucide:x" aria-label="Clear" />
  </InputGroup.Trailing>
</InputGroup>
```

### Styling and forms

- **Shared frame**: `InputGroup` owns the border, background, radius, and focus/invalid frame via `size` and `variant`. The control's own `variant` applies only outside a group, while disabled state stays on the control.
- **Size and slot precedence**: size resolves from the control's explicit `size`, group `size`, `Field` size, then theme defaults. `classes.leading` / `classes.trailing` and `styles` set group-wide presentation; each part's `class` and `style` override them.
- **Form and focus**: keep `name`, `value`, `onValueChange`, `required`, `disabled`, `readOnly`, and ARIA attributes on the control (`InputGroup` does not register a form field). Clicking non-interactive group space focuses the control, while buttons and links keep their own focus behavior.
