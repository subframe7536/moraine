`createTree` returns a reactive store that carries the tree state and the components bound to it.
`tree.Tree` renders the visible items. With `virtualRender`, flattened rows live in the tree root
(the scroll container); otherwise a branch's `content` nests its child items.

## Usage

Create the tree with `createTree`, then render `tree.Tree`. Items are plain data: describe them with
`getKey` and `getChildren`. There is no static `<Tree>` component, so every tree owns its state.

```tsx
import { createTree } from 'moraine'

interface FileNode {
  id: string
  name: string
  children?: FileNode[]
}

export function Files(props: { files: FileNode[] }) {
  const tree = createTree<FileNode>({
    items: () => props.files,
    getKey: (node) => node.id,
    getChildren: (node) => node.children,
    getTextValue: (node) => node.name,
  })

  return <tree.Tree aria-label="Project files" />
}
```

Always give the tree an accessible name with `aria-label` or `aria-labelledby`.

### Instance

The store exposes reactive `expandedKeys`, `selectedKeys`, `checkedKeys`, `focusedKey`, and
`loadingKeys`, the visible `flattenedItems`, and imperative methods: `expand`, `collapse`,
`toggle`, `expandAll`, `collapseAll`, `expandTo`, `select`, `deselect`, `toggleSelect`,
`selectAll`, `clearSelection`, `check`, `uncheck`, `toggleCheck`, `isLoading`, and `focus`.
`tree.getItem(key)` returns a stable item handle with `level`, `posInSet`, `setSize`,
`isExpanded`, `isSelected`, `isLoading`, `isFocused`, `isDisabled`, `checkedState`, and actions.
Disabled items are skipped by keyboard navigation and cannot be selected, expanded, or checked.

### Expansion

Use `defaultExpandedKeys` for uncontrolled expansion, or `expandedKeys` with `onExpandedChange` to own
it. Options are read reactively, so pass controlled values with getters. Row clicks toggle branches
unless `expandOnClick` is `false`; the trigger always toggles. Set `trigger={false}` to render no
chevron at all — rows then always toggle, whatever `expandOnClick` says.

The height animation when a branch expands or collapses is on by default; disable it with
`transition={false}` on `tree.Tree`. Collapsed branches unmount their children unless
`unmountOnHide={false}`.

```tsx
const [expanded, setExpanded] = createSignal(['src'])
const tree = createTree({
  items,
  getKey,
  getChildren,
  get expandedKeys() {
    return expanded()
  },
  onExpandedChange: setExpanded,
})
```

### Icons

Set `getIcon` to render a prefix icon in the default item. It receives the item instance, so the
icon can react to `hasChildren`, `isExpanded`, or `isLoading`. Returning `undefined` renders no
icon; use `tree.ItemIcon` directly when composing a custom `itemRender`. The chevron is changed
with `triggerIcon` on `tree.Tree`, the glyph shown while a branch loads with `loadingIcon`, and
`tree.ItemTrigger` accepts an `icon` override per item.

```tsx
const tree = createTree({
  items,
  getKey,
  getChildren,
  getIcon: (item) => (item.hasChildren ? 'i-lucide:folder' : 'i-lucide:file'),
})
```

### Selection

`selectionMode` is `single` by default. Use `multiple` for <kbd>Ctrl</kbd> / <kbd>Shift</kbd> clicks and

<kbd>Ctrl</kbd>+<kbd>A</kbd>, or `none` to turn selection off. Control it with `selectedKeys` and
`onSelectionChange`.

### Checkboxes

Set `checkable` to add the check state. The default item then renders a bound `tree.ItemCheckbox`
in each row. By default, checking a branch checks its descendants and a branch with a mix of checked
descendants is indeterminate; set `checkCascade={false}` to treat every item independently. Checked
branches pass their state to children that load later.

To place the checkbox in a custom item, compose `tree.ItemCheckbox`. It is bound to the item's check
state, inherits the tree `size`, and is hidden from assistive technology and removed from the tab
order because the `treeitem` itself carries `aria-checked`. Use `size`, `checkedIcon`, and
`indeterminateIcon` to adjust its appearance.

```tsx
<tree.Tree
  itemRender={(item) => (
    <tree.Item item={item}>
      <tree.ItemTrigger />
      <tree.ItemCheckbox />
      <tree.ItemLabel />
    </tree.Item>
  )}
/>
```

### Async children

Provide `loadChildren` to fetch children on demand. Items that have no `getChildren` result and are not
`isLeaf` become lazy branches. Expanding one waits for the promise: the trigger shows the loading icon and
the item sets `aria-busy`. A successful load calls `onLoadChildrenComplete`; a failed one calls
`onLoadChildrenError` and leaves the branch collapsed so the user can retry. Branches still loading
appear in `loadingKeys` and through `tree.isLoading(key)`.

### Virtualization

Pass `virtualRender` from `createListVirtualizer` to render only the rows near the viewport. The tree
root is the scroll container, so give it a bounded height and `overflow-auto`. Expanded branches are
flattened into one list, and each row keeps `aria-level`, `aria-posinset`, and `aria-setsize` so
assistive technology still reads the full hierarchy. Pass `scrollToItem` so moving focus to a row
outside the window scrolls it into view first.

```tsx
import { createListVirtualizer } from 'moraine/virtualizer'

const virtualizer = createListVirtualizer({
  estimateSize: () => 32,
  getItemKey: (item) => item.key,
})

<tree.Tree
  aria-label="Files"
  virtualRender={virtualizer.virtualRender}
  scrollToItem={(_item, index) => virtualizer.scrollToIndex(index)}
  class="h-80 overflow-auto"
/>
```

### Custom items

`itemRender` renders one visible item. Use `tree.Item` as its root and compose `tree.ItemTrigger`,
`tree.ItemCheckbox`, `tree.ItemIcon`, `tree.ItemLabel`, and `tree.ItemAction`. Without `itemRender`,
the default item renders the trigger, a checkbox when `checkable`, the icon returned by `getIcon`,
the label, and the `actionRender` actions.

### Row actions

`actionRender` renders trailing controls for every item in the default item, wrapped in
`tree.ItemAction` at the end of the row. In a custom `itemRender`, place `tree.ItemAction` last.
Actions are always rendered in-flow and visible; the slot carries no built-in hover reveal, so
override the `action` slot to show them on demand — the row is marked `group/tree-row` for that.
Clicks inside the actions never select or expand the item.

```tsx
<tree.Tree
  actionRender={(item) => (
    <Button
      variant="ghost"
      size="icon-xs"
      leading="i-lucide:trash-2"
      aria-label={`Delete ${item.textValue}`}
    />
  )}
/>
```

### Indentation

Every item sets `--mo-tree-level` (zero for roots), and rows indent by that level times
`--mo-tree-indent`. Indent guides are drawn for each ancestor level; set `indentGuide={false}` to hide
them. The tree root declares the geometry variables, so overriding them in the `tree.Tree` `style`
applies to every item:

| Variable           | Default        | Description                                       |
| ------------------ | -------------- | ------------------------------------------------- |
| `--mo-tree-indent` | `1.25rem`      | Indentation added per nesting level.              |
| `--mo-tree-gap`    | Size dependent | Gap between the trigger, icon, and label.         |
| `--mo-tree-gutter` | `0.25rem`      | Horizontal margin between rows and the tree edge. |
| `--mo-tree-pad`    | `0.5rem`       | Row start padding before indentation.             |

```tsx
<tree.Tree
  style={{
    '--mo-tree-indent': '1.5rem',
    '--mo-tree-gap': '0.25rem',
  }}
/>
```

### Keyboard interaction

| Key                                       | Description                                                                                                 |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| <kbd>ArrowDown</kbd> / <kbd>ArrowUp</kbd> | Moves focus to the next or previous visible item.                                                           |
| <kbd>ArrowRight</kbd>                     | Expands a collapsed branch, or moves to its first child when expanded.                                      |
| <kbd>ArrowLeft</kbd>                      | Collapses an expanded branch, or moves to the parent.                                                       |
| <kbd>Home</kbd> / <kbd>End</kbd>          | Moves focus to the first or last visible item.                                                              |
| <kbd>Enter</kbd>                          | Calls `onAction`; without it, selects the item, or toggles the branch when `selectionMode` is `none`.       |
| <kbd>Space</kbd>                          | Toggles the check state when `checkable`; toggles selection in `multiple` mode; otherwise selects the item. |
| <kbd>Shift</kbd>+<kbd>ArrowDown/Up</kbd>  | Extends the selection in `multiple` mode.                                                                   |
| <kbd>Ctrl</kbd>+<kbd>A</kbd>              | Selects every enabled item in `multiple` mode.                                                              |
| <kbd>\*</kbd>                             | Expands every sibling of the focused item.                                                                  |
| Characters                                | Moves focus to the next item whose text starts with the typed characters; disable with `typeahead={false}`. |

The horizontal arrows swap in right-to-left layouts. Only one item is in the tab order at a time.
