## Usage

Use Popover for anchored interactive content that does not need a labeled modal surface:

- [Tooltip](/components/tooltip): brief, non-interactive hint.
- [DropdownMenu](/components/dropdown-menu): compact action list from a visible trigger.
- [Dialog](/components/dialog) or [Sheet](/components/sheet): modal tasks that take over the page.
- [BaseDialog](/components/base-dialog): headless primitive to compose backdrop and content yourself.

```tsx
import { Button, Popover } from 'moraine'

export function Example() {
  return (
    <Popover>
      <Popover.Trigger as={Button}>Details</Popover.Trigger>
      <Popover.Content>More information</Popover.Content>
    </Popover>
  )
}
```

### Trigger modes and state

Click toggles the popover by default. Use `open`, `defaultOpen`, and `onOpenChange` when the application coordinates visibility.

Set `openOnHover` to open when a mouse pointer enters the trigger or the trigger receives keyboard focus, and close `closeDelay` ms after the pointer or focus leaves both trigger and content (`openDelay` and `closeDelay` default to `100` ms). When `openOnHover` is enabled:

- Clicking the trigger only opens the popover.
- Touch hover is ignored.
- Outside focus no longer dismisses the content.
- Closing does not restore focus to the trigger unless `finalFocus` is set.

```tsx
<Popover>
  <Popover.Trigger as={Button}>Filter</Popover.Trigger>
  <Popover.Content>Click stays open while you choose filters.</Popover.Content>
</Popover>
<Popover openOnHover openDelay={150} closeDelay={100}>
  <Popover.Trigger as={Button}>Profile</Popover.Trigger>
  <Popover.Content>Hover or focus to preview.</Popover.Content>
</Popover>
```

### Placement

- `placement` (`'top'`, `'right'`, `'bottom'`, or `'left'`; default `'bottom'`) and `align` (`'start'`, `'center'`, or `'end'`; default `'center'`): position the content relative to the trigger.
- `gutter` and `overflowPadding` (both default to `4` px): set the gap to the trigger and the minimum distance from the viewport edge.
- `flip` and `slide` (both default to `true`): flip to the opposite side when `placement` does not fit and slide along the trigger edge to stay inside the viewport. Read the active side from `data-side` on the content.

```tsx
<Popover placement="right" align="start" gutter={8}>
  <Popover.Trigger as={Button}>Details</Popover.Trigger>
  <Popover.Content>Opens to the right of the trigger.</Popover.Content>
</Popover>
```

### Dismissal and accessibility

Escape and outside interaction close a popover. Closing restores focus to the trigger, except after an outside press or focus move where focus has already moved elsewhere. Give `Popover.Content` an accessible name with `aria-label` when it has no visible heading.

`closeOnEscape` and `closeOnOutsideClick` control dismissal independently, and `preventScroll` locks body scroll while the popover is open.

```tsx
<Popover>
  <Popover.Trigger as={Button}>Filter</Popover.Trigger>
  <Popover.Content aria-label="Filter settings">Press Escape or click outside.</Popover.Content>
</Popover>
<Popover closeOnEscape={false} closeOnOutsideClick={false} onClosePrevented={onBlocked}>
  <Popover.Trigger as={Button}>Keep open</Popover.Trigger>
  <Popover.Content>Outside click and Escape are blocked.</Popover.Content>
</Popover>
```

### Keyboard interaction

Keyboard activation follows the trigger element. Escape requests dismissal when `closeOnEscape` allows it, and focusable controls inside the content participate in normal document focus order.

With `openOnHover`:

- <kbd>Tab</kbd> from the trigger moves into the open content.
- <kbd>Tab</kbd> from the last control inside the content moves to the next focusable element after
  the trigger.
- <kbd>Shift</kbd> + <kbd>Tab</kbd> from the first control returns to the trigger.
