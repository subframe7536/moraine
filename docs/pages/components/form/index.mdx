## Usage

Use `createForm` for schema validation, submission, and reset. It returns a reactive Formisch store
with bound `form.Form` and `form.Field` components. Use standalone [Field](/components/field)
when you only need labels and messages.

```tsx
import { createForm, Input, Button, Switch, InputGroup, Icon } from 'moraine'
import * as v from 'valibot'

const schema = v.object({
  email: v.pipe(v.string(), v.email('Enter a valid email address')),
  enabled: v.boolean(),
})

export function NotificationForm() {
  const form = createForm({
    schema,
    initialInput: { email: '', enabled: false },
  })

  return (
    <form.Form onSubmit={(output) => console.log(output)}>
      <form.Field name="email" label="Email Address">
        <InputGroup>
          <InputGroup.Leading>
            <Icon name="i-lucide:mail" />
          </InputGroup.Leading>
          <Input />
        </InputGroup>
      </form.Field>
      <form.Field name="enabled" label="Enable Notifications">
        <Switch />
      </form.Field>
      <Button type="submit">Save Changes</Button>
    </form.Form>
  )
}
```

### Submission

`form.Form` renders Formisch's `Form`: it prevents native navigation, validates the schema, focuses
the first invalid field in schema order, and calls `onSubmit` with the validated schema output
(after any Valibot transforms) and the native `SubmitEvent`. An invalid submit does not call
`onSubmit`. Native `action` and `method` attributes do not enable a browser navigation submit. The
returned store also supports Formisch's public methods and helpers, including `submit(form)` and
programmatic field focus.

`form.isSubmitting` stays `true` until a promise returned by `onSubmit` settles. A thrown or
rejected error is stored in the form `errors` rather than propagating; an error without a `message`
is recorded as the `unknownError` translation. `form.Form` does not disable child controls during
submission, so derive button loading or disabled state from `form.isSubmitting`.

```tsx
<Button type="submit" loading={form.isSubmitting} disabled={form.isSubmitting}>
  Save draft
</Button>
```

### Root styling

`<form.Form>` owns only its native form root, exposed as the `root` slot. Use `class` and `style`
(or `classes={{ root }}` and `styles={{ root }}`) for an individual form, or configure `form.base.root`
in your Theme. The root sets `data-submitting` while `form.isSubmitting` is `true`. Style the parts
of a field through the slot maps on `form.Field`.

### Bound field outside the form root

`form.Field` captures the Formisch store from `createForm()`, so it works without rendering
`form.Form`. Use the standalone [`Field`](/components/field) when schema binding is not needed.

```tsx
const form = createForm({ schema })

<form.Field name="email" label="Email">
  <Input />
</form.Field>
```

### Field labels and messages

`<form.Field>` accepts every [Field](/components/field) prop except `name`, which takes a schema
path: `label`, `hint`, `description`, `help`, `required`, `orientation`, and so on. Its error is the
first schema error unless you pass `error`. Moraine controls link descriptions and error messages
through ARIA attributes.

```tsx
<form.Field
  name="repoName"
  label="Repository name"
  description="Must be URL-friendly and unique within your organization."
  required
>
  <Input placeholder="moraine-app" />
</form.Field>
```

### Nested and array paths

Target nested object and array fields with a path array such as `['profile', 'email']` or
`['tags', 0]`. Path types are validated and autocompleted from the schema. A dotted string like
`'profile.email'` is read as one top-level key, not a path.

```tsx
<form.Field name={['profile', 'email']} label="Profile Email">
  <Input type="email" />
</form.Field>
```

### Reset

A `type="reset"` button restores the initial store input snapshot and clears validation metadata.
The restore runs in a microtask after the `reset` event and is skipped if a handler calls
`event.preventDefault()`. Handle `onReset` on `form.Form` when your code needs to react to it.

```tsx
<form.Form onReset={() => setResetCount((count) => count + 1)}>
  <form.Field name="name" label="Name">
    <Input />
  </form.Field>
  <Button type="reset" variant="outline">
    Reset
  </Button>
</form.Form>
```
