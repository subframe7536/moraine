## Usage

Use ScrollArea to constrain overflowing content. Scrolling stays native: wheel, touch, keyboard,
and scroll anchoring behave as in any scroll container. ScrollArea hides the native scrollbar and
draws its own scrollbar over the content.

```tsx
import { For } from 'solid-js'
import { ScrollArea } from 'moraine'

export function Example() {
  return (
    <ScrollArea class="h-48 w-full" role="region" aria-label="Recent activity">
      <For each={Array.from({ length: 12 }, (_, index) => index + 1)}>
        {(entry) => <p class="py-2 text-sm">Activity entry {entry}</p>}
      </For>
    </ScrollArea>
  )
}
```

### Structure and sizing

Set a height or maximum height on the root for vertical scrolling and a width for horizontal
scrolling. The root positions the scrollbars; the `viewport` scrolls; the `content` wraps the
children. Put content layout such as `flex` and `gap` on `classes.content`, not on the root.

`class`, `style`, `ref`, and other attributes such as `role` and `aria-label` go to the root.
`onScroll` and `tabIndex` go to the viewport, and `viewportRef` receives it. The viewport joins
the tab order while its content overflows and leaves it when the content fits; pass `tabIndex` to
override this.

### Orientation

`orientation` selects the scrollable axes: `vertical` (default), `horizontal`, or `both`. With
`both`, the two scrollbars meet at the `corner`. Horizontal and two-axis content grows to its
natural width.

```tsx
<ScrollArea orientation="horizontal" class="max-w-lg" classes={{ content: 'flex gap-3' }}>
  {milestones}
</ScrollArea>
```

### Scrollbars

`scrollbar` selects how scrollbars appear:

| Value    | Behavior                                                            |
| -------- | ------------------------------------------------------------------- |
| `auto`   | Custom scrollbars while an axis overflows. This is the default.     |
| `always` | Custom scrollbars at all times, even when content fits.             |
| `hover`  | Custom scrollbars while the pointer is over the area or it scrolls. |
| `scroll` | Custom scrollbars while the area scrolls.                           |
| `native` | Browser scrollbars.                                                 |
| `hidden` | No scrollbars; wheel, touch, and keyboard scrolling still work.     |

`hover` and `scroll` scrollbars stay visible for `scrollHideDelay` milliseconds (default `600`)
after activity ends. Drag the thumb to scroll, or press the track to jump to that position.
Scrollbars are hidden from assistive technology; keyboard scrolling goes through the focusable
viewport.

### Edge shadows

Set `shadow` to fade content out at edges that have more content beyond them. The shadow grows with
the remaining distance up to `shadowSize` pixels (default `40`), so it appears gradually instead of
switching on. The mask fades content into the background behind the container.

```tsx
<ScrollArea shadow shadowSize={24} class="h-48" role="region" aria-label="Activity">
  {entries}
</ScrollArea>
```

### Overflow state

`onOverflowChange` receives `{ x: { start, end }, y: { start, end } }` whenever the edges with
more content beyond them change. `start` and `end` are logical: in RTL content, the `x` start
edge is on the right. `edgeThreshold` sets how close to an edge, in pixels, scrolling counts as
reaching it.

`onReachStart` and `onReachEnd` receive the axis when scrolling reaches an edge of an overflowing
axis. Combine `onReachEnd` with `edgeThreshold` to load more content before the end.

`controllerRef` receives a controller with the reactive `overflow` state and
`scrollToEdge(axis, edge, options)`.

```tsx
let controller: ScrollAreaT.Controller | undefined

;<ScrollArea
  edgeThreshold={48}
  onReachEnd={(axis) => axis === 'y' && loadMore()}
  controllerRef={(value) => (controller = value)}
>
  {messages}
</ScrollArea>

controller?.scrollToEdge('y', 'end', { behavior: 'smooth' })
```

### Virtualization

Pass `items` and an `itemRender` component to render a collection. Add a `virtualizer` from
`createListVirtualizer()` to render only the visible items; the viewport is its scroll container.
Spread `props.props` on each row. Create the virtualizer with `horizontal` for
`orientation="horizontal"`. `itemRender` takes the place of `children`.

```tsx
import { createListVirtualizer } from 'moraine/virtualizer'

const virtualizer = createListVirtualizer<string>({ estimateSize: () => 32 })

<ScrollArea
  class="h-80"
  items={lines}
  virtualizer={virtualizer}
  itemRender={(props) => <div {...props.props}>{props.item}</div>}
/>
```

### Data attributes and CSS variables

The root carries `data-orientation`, `data-overflow-x` and `data-overflow-y` while an axis
overflows, `data-overflow-{x,y}-{start,end}` for each overflowing edge, `data-scrolling`, and
`data-hovering`. Each scrollbar carries `data-orientation`, `data-visible`, `data-dragging`, and
`data-corner` while the corner is shown; the corner carries `data-visible`.

The root also exposes the remaining scroll distance of each edge in pixels as
`--scroll-area-overflow-x-start`, `--scroll-area-overflow-x-end`,
`--scroll-area-overflow-y-start`, and `--scroll-area-overflow-y-end`. Use them for custom
edge effects.

### Theme and instance overrides

Set `scrollArea.defaultVariants` to choose the scrollbar mode or enable shadows across a provider;
`scrollbar: 'native'` restores browser scrollbars everywhere. The recipe exposes
`--scroll-area-shadow-size` and the mask layers `--scroll-area-shadow-y` and
`--scroll-area-shadow-x`.

The shadow size resolves in this order, highest first: root `style`, `styles.root`, an explicit
`shadowSize`, then recipe and Theme defaults.
