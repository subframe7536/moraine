## Usage

Use ScrollArea to constrain overflowing content while keeping native scrolling. Enable `shadow` to
fade the edges that have more content beyond the viewport.

```tsx
import { For } from 'solid-js'
import { ScrollArea } from 'moraine'

export function Example() {
  return (
    <ScrollArea class="h-48 w-full" shadow role="region" aria-label="Recent activity">
      <For each={Array.from({ length: 12 }, (_, index) => index + 1)}>
        {(entry) => <p class="py-2 text-sm">Activity entry {entry}</p>}
      </For>
    </ScrollArea>
  )
}
```

### Native scrolling and sizing

Set a height or maximum height for vertical scrolling and a width for horizontal scrolling.
ScrollArea is one `<div>` root that renders its children directly. Use `class`, `classes.root`,
`style`, or `styles.root` for instance styling, such as `flex` and `gap` on the root.

The root joins the tab order when its content overflows (`tabIndex={0}`) and leaves it when the
content fits. Add `role="region"` and an accessible label when the content forms a named region, or
`tabIndex={-1}` to keep it out of the tab order. Native scroll events and refs reach the root.

### Optional shadows

Shadows are disabled by default. Set `shadow` to enable CSS mask fades at overflowing edges. A
container at the start shows a trailing fade; between the edges it shows both fades; at the end it
shows a leading fade. Content that fits has no automatic fade.

The mask fades content into the background behind the container. Scroll position, content changes,
and size changes update the visible edges.

```tsx
<ScrollArea shadow class="h-48" role="region" aria-label="Activity">
  {entries}
</ScrollArea>
```

### Horizontal scrolling and RTL

Set `orientation="horizontal"` and make the content wider than the viewport. Use `hideScrollbar` to
hide the native scrollbar while retaining wheel, touch, and keyboard scrolling. Horizontal edge
detection also supports `dir="rtl"`; `left` and `right` refer to physical edges.

```tsx
<ScrollArea orientation="horizontal" shadow hideScrollbar dir="rtl" class="flex gap-3 max-w-lg">
  {milestones}
</ScrollArea>
```

### Shadow size and visibility

The default fade size is `40px`. Pass `shadowSize` to set its length in pixels. `offset` adds a
margin near each edge within which that edge's automatic fade remains hidden.

`visibility="auto"` follows measured overflow. Choose `top`, `bottom`, or `both` for vertical
scrolling, and `left`, `right`, or `both` for horizontal scrolling to force visible edges. `none`
suppresses every fade. Manual visibility still requires `shadow`.

`onVisibilityChange` reports measured overflow changes while shadows are enabled, including when
visibility is forced. It receives `top`, `bottom`, `left`, `right`, `both`, or `none`.

```tsx
<ScrollArea
  shadow
  shadowSize={24}
  offset={8}
  visibility="auto"
  onVisibilityChange={setOverflow}
  class="h-48"
  role="region"
  aria-label="Notifications"
>
  {items}
</ScrollArea>
```

### Theme and instance overrides

Set `scrollArea.defaultVariants` to enable shadows or hide scrollbars across a provider. The recipe
exposes `--scroll-area-shadow-size` and the gradient stop lists `--scroll-area-shadow-start` and
`--scroll-area-shadow-end`. A single-edge mask uses one stop list; the double-edge mask combines
both. Express size-dependent stops with `var(--scroll-area-shadow-size)` so `shadowSize` keeps
affecting them.

The size variable resolves in this order, highest first: root `style`, `styles.root`, an explicit
`shadowSize`, then recipe and Theme defaults. Omitting `shadowSize` keeps the Theme value. Recipe
variables are written on the root, so an ancestor's same-named variable does not replace the local
default.

```tsx
<ScrollArea shadow shadowSize={12} class="h-48" role="region" aria-label="Updates">
  {updates}
</ScrollArea>
```
