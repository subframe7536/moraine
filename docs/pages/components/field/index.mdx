Help and error are mutually exclusive; the error replaces help while it is displayed.

## Usage

Use Field to label a standalone control and attach description, help, and error text. It registers
the nested control, passes `size`, `disabled`, `required`, and `readOnly` down to it, and wires the
ARIA relationships. It does not validate or submit values.

For schema binding, use `form.Field` from [createForm](/components/form). Put a Moraine control
inside Field so the label, description, and error IDs attach to the actual focusable element. For
local validation, pass the current message to `error`.

Children can be JSX or a render function that receives the field state as props, such as
`(state) => ...`, where `state.error` is the effective error (`false` when `error={false}`
suppresses it).

```tsx
import { Field, Input } from 'moraine'

export function Example() {
  return (
    <Field label="Email">
      <Input name="email" type="email" />
    </Field>
  )
}
```

### Text and messages

| Prop          | Placement and behavior                                                      |
| ------------- | --------------------------------------------------------------------------- |
| `label`       | A `<label>` pointing to the nested control; also its `aria-labelledby`      |
| `hint`        | Beside the label, such as "Optional"; shown only when the field has a label |
| `description` | Under the label, above the control; linked with `aria-describedby`          |
| `help`        | Under the control; hidden while an error is displayed                       |
| `error`       | Under the control, replacing `help`; marks the control `aria-invalid`       |

When `error` is `undefined` or `null`, Field shows the error of its form binding. `error={false}`
suppresses any error, including the bound one. Empty content such as `''` displays nothing.

Set `required`, `disabled`, or `readOnly` on Field to pass the state to nested controls; a control's
own prop takes precedence. `required` also adds a required indicator to the label.

### Hidden labels

Use `hiddenLabel` when a compact control needs an accessible name without a visible label. It
keeps the label association without reserving label spacing or an empty horizontal label column.
A non-empty `label` takes precedence over `hiddenLabel`. Hint and description text remain visible;
help and error text keep their usual placement.

```tsx
<Field hiddenLabel="Filter commands" help="Search by command name or shortcut.">
  <Input placeholder="Filter commands…" />
</Field>
```

For a switch with a trailing visible label, use `<Switch label="Auto refresh" />`.

### Orientation

`orientation="horizontal"` lays the label beside the control, as in a settings row. `'vertical'` is
the default stacked layout.

```tsx
<Field orientation="horizontal" label="Display name" description="Shown to other users.">
  <Input />
</Field>
```
