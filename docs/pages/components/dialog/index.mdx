Content is portaled and renders inside the overlay element. With `overlay={false}`, that element is an unstyled wrapper without the `overlay` slot.

## Usage

Use Dialog for a labeled modal task with title, description, body, and footer. The trigger and
content share disclosure state through the root.

- Use [BaseDialog](/components/base-dialog) when you compose backdrop and content yourself.
- Use [Sheet](/components/sheet) or [Drawer](/components/drawer) for a panel from a viewport edge.
- Use [Popover](/components/popover) for anchored interactive content that should not take over the
  page.
- Use [Tooltip](/components/tooltip) for a brief non-interactive hint.
- Use [DropdownMenu](/components/dropdown-menu) or [ContextMenu](/components/context-menu) for an
  action list.
- Use [Alert Dialog](/components/alert-dialog) for confirm, info, warning, error, and success
  prompts opened from an event handler.

```tsx
import { Button, Dialog } from 'moraine'

export function Example() {
  return (
    <Dialog>
      <Dialog.Trigger as={Button}>Open</Dialog.Trigger>
      <Dialog.Content title="Settings">
        <Dialog.Body>Preferences</Dialog.Body>
        <Dialog.Footer>
          <Dialog.Close as={Button}>Done</Dialog.Close>
        </Dialog.Footer>
      </Dialog.Content>
    </Dialog>
  )
}
```

### Content composition

Use Content `title` and `description` for simple cases:

```tsx
<Dialog>
  <Dialog.Content title="Settings" description="Update your account.">
    <Dialog.Body>...</Dialog.Body>
    <Dialog.Footer>...</Dialog.Footer>
  </Dialog.Content>
</Dialog>
```

For a custom header layout, compose the anatomy parts:

```tsx
<Dialog.Content>
  <Dialog.Header>
    <Dialog.Title>Settings</Dialog.Title>
    <Dialog.Description>Update your account.</Dialog.Description>
  </Dialog.Header>
  <Dialog.Body>...</Dialog.Body>
  <Dialog.Footer>...</Dialog.Footer>
</Dialog.Content>
```

An explicit `Dialog.Header` replaces the header generated by Content's `title` and `description`.
`Dialog.Title` and `Dialog.Description` connect their IDs to the surface's accessible name and
description. Without a visible title, set `aria-label` or `aria-labelledby` on Content.

`Dialog.Close` is an explicit close control you can place inside the root; it is separate from
Content's automatic corner close button. Set root `closable={false}` to hide the corner button, or
`closeIcon` to replace its icon. Its accessible label comes from the `close` message; override it
with root `translations` (see [Localization](/docs/localization)).

Root `transition={false}` turns off the enter and exit animations, so content and overlay unmount as
soon as the dialog closes.

### Focus and dismissal

`modal` defaults to `true`: focus stays inside the surface, outside content is hidden from assistive
technology, and native outside pointer actions are prevented. Closing restores focus to the trigger.

Use `initialFocus` to choose the element that receives focus on open, or `false` to skip the move,
and `finalFocus` to choose where focus returns. Both apply only while `modal` is `true`.

Setting `modal={false}` allows focus to leave the surface, but does not disable Escape or outside
dismissal. `closeOnOutsideClick` and `closeOnEscape` control those close requests. Both default to
`true`. `preventScroll` locks body scroll and defaults to the value of `modal`, so a
non-modal surface leaves the page scrollable unless `preventScroll` is set.

### Styling and portal

Apply `class` and object `style` directly to each rendered part. Root `classes` and `styles` set
slot defaults for every part: `trigger`, `overlay`, `content`, `header`, `title`, `description`,
`contentClose`, `body`, and `footer`. See
[Customization](/docs/customization#the-4-layer-override-hierarchy) for precedence.

Set root `mount` to place Content in a chosen container. This also works for controlled
surfaces without a Trigger.

### Nested overlays

Nested roots keep dismissal and focus restoration local to the active layer. Escape closes the
topmost dialog or popover, then returns focus to its trigger inside the parent dialog.

```tsx
<Dialog>
  <Dialog.Content title="Workspace settings">
    <Popover>
      <Popover.Trigger as={Button}>Help</Popover.Trigger>
      <Popover.Content aria-label="Settings help">Workspace-only changes.</Popover.Content>
    </Popover>
    <Dialog>
      <Dialog.Trigger as={Button}>Confirm</Dialog.Trigger>
      <Dialog.Content title="Confirm changes">...</Dialog.Content>
    </Dialog>
  </Dialog.Content>
</Dialog>
```

### State and dismissal

Use controlled `open` with `onOpenChange` when the surrounding flow owns visibility.
`closeOnOutsideClick={false}` blocks an outside pointer press, and `closeOnEscape={false}` blocks
Escape. Both report the attempt through `onClosePrevented`. Provide a clear explicit close path when
either one is blocked.

```tsx
<Dialog
  open={open()}
  onOpenChange={setOpen}
  closeOnOutsideClick={false}
  closeOnEscape={false}
  onClosePrevented={onBlocked}
>
  <Dialog.Content title="Unsaved changes">
    <Dialog.Footer>
      <Button onClick={() => setOpen(false)}>Discard</Button>
      <Button onClick={() => setOpen(false)}>Save</Button>
    </Dialog.Footer>
  </Dialog.Content>
</Dialog>
```

### Layout and exit

Use root `scrollable` when a long panel should scroll as a whole inside the backdrop instead of
being capped to the viewport height, or `fullscreen` for a full-viewport task. `onExitComplete`
runs after the overlay and content finish their exit animations.

```tsx
<Dialog scrollable>
  <Dialog.Content title="Release notes">...</Dialog.Content>
</Dialog>
<Dialog fullscreen onExitComplete={() => setStatus('Exit animation completed')}>
  <Dialog.Content title="Release notes">...</Dialog.Content>
</Dialog>
```

### Keyboard interaction

| Key                    | Description                                                        |
| ---------------------- | ------------------------------------------------------------------ |
| <kbd>Escape</kbd>      | Requests dismissal when `closeOnEscape` is not `false`.            |
| <kbd>Tab</kbd>         | Moves focus forward through focusable controls inside the dialog.  |
| <kbd>Shift + Tab</kbd> | Moves focus backward through focusable controls inside the dialog. |
