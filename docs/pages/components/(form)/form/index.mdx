Each `form.Field` uses the Field layout; the bound `form.Form` owns only its native form root.

## Usage

Use `createForm` for schema validation, submission, and reset. It returns a reactive Formisch store
with bound `form.Form` and `form.Field` components. Use standalone [Field](/components/field)
when you only need labels and messages.

```tsx
import { createForm, Input, Button, Switch, InputGroup, Icon } from 'moraine'
import * as v from 'valibot'

const schema = v.object({
  email: v.pipe(v.string(), v.email('Enter a valid email address')),
  enabled: v.boolean(),
})

export function NotificationForm() {
  const form = createForm({
    schema,
    initialInput: { email: '', enabled: false },
  })

  return (
    <form.Form onSubmit={(output) => console.log(output)}>
      <form.Field name="email" label="Email Address">
        <InputGroup>
          <InputGroup.Leading>
            <Icon name="i-lucide:mail" />
          </InputGroup.Leading>
          <Input />
        </InputGroup>
      </form.Field>
      <form.Field name="enabled" label="Enable Notifications">
        <Switch />
      </form.Field>
      <Button type="submit">Save Changes</Button>
    </form.Form>
  )
}
```

### Submission

`form.Form` prevents native navigation, validates the schema, and calls `onSubmit` with the
validated output. Native `action` and `method` attributes do not enable a browser navigation
submit. The returned store also supports Formisch's public methods and helpers, including
programmatic field focus.

`form.Form` does not automatically disable child controls during submission. Read
`form.isSubmitting` to derive button loading or disabled state while an async submit is in flight.

```tsx
<Button type="submit" loading={form.isSubmitting} disabled={form.isSubmitting}>
  Save draft
</Button>
```

### Root styling

`<form.Form>` owns only its native form root. Use direct `class` and `style` props for an
individual form, or configure `form.base.root` in your Theme. Slot maps remain available on
`form.Field`, but the bound Form component does not accept `classes` or `styles`.

### Bound field outside the form root

`form.Field` captures the Formisch store from `createForm()`, so it can be used without rendering
`form.Form`. Use the standalone [`Field`](/components/field) when schema binding is not needed.

```tsx
const form = createForm({ schema })

<form.Field name="email" label="Email">
  <Input />
</form.Field>
```

### Field labels and messages

Configure `label`, `hint`, `description`, `help`, and `required` on `<form.Field>`. Supported
Moraine controls link helper descriptions and error messages through ARIA attributes.

```tsx
<form.Field
  name="repoName"
  label="Repository name"
  description="Must be URL-friendly and unique within your organization."
  required
>
  <Input placeholder="moraine-app" />
</form.Field>
```

### Nested and array paths

Target nested object and array fields with path tuples such as `['profile', 'email']`. Path types
are validated and autocompleted from the schema.

```tsx
<form.Field name={['profile', 'email']} label="Profile Email">
  <Input type="email" />
</form.Field>
```

### Reset

A `type="reset"` button restores the initial store input snapshot and clears validation metadata.
Handle `onReset` on `form.Form` when the page needs to react to that restore.

```tsx
<form.Form onReset={() => setResetCount((count) => count + 1)}>
  <form.Field name="name" label="Name">
    <Input />
  </form.Field>
  <Button type="reset" variant="outline">
    Reset
  </Button>
</form.Form>
```
