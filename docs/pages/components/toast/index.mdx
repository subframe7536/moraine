`<Toast />` renders a portaled `root` with `role="region"` and `aria-live="polite"`, holding one
`list` stack per placement. Each notification is an `item`. The `icon` reflects the type, and the
`action`, `cancel`, `close`, and `progress` slots appear when the matching option is set.

## Usage

Use Toast for temporary feedback that stays in the page. Use [Alert Dialog](/components/alert-dialog)
when the next step should wait for an explicit choice.

Mount `<Toast />` once. It holds no open state. Trigger notifications from event handlers with the
static methods.

```tsx
import { Button, Toast } from 'moraine'

export function Example() {
  return (
    <>
      <Button onClick={() => Toast.success({ title: 'Preferences saved' })}>Save</Button>
      <Toast />
    </>
  )
}
```

### Shared model

Toast and [Alert Dialog](/components/alert-dialog) use the same options, actions, handle, and close
reasons. Every instance is created with a static method that takes an options object. Call options
override the host defaults, including `false`, `0`, and `null`. A call before the host is mounted
throws. On the server the call returns a handle whose `result()` is already `'api'`.

```ts
interface Action {
  label?: JSX.Element
  variant?: ButtonT.Variants['variant']
  leading?: IconT.Name
  disabled?: boolean
  onClick?: (event?: MouseEvent) => void | Promise<unknown>
}

type CloseReason = 'action' | 'cancel' | 'dismiss' | 'timeout' | 'api'

interface Handle {
  id: string | number
  update: (options: UpdateOptions) => void
  close: () => void
  result: () => Promise<CloseReason>
}
```

`action.onClick` and `cancel.onClick` run before the instance closes. A returned promise shows
loading on that button, disables the other one, and pauses the toast timer. A dialog also blocks
Escape, the overlay, and the corner close button. Calling `event.preventDefault()`, rejecting, or
throwing leaves the instance open. A throw or rejection is reported with `console.error`.
Otherwise the instance closes with `'action'` or `'cancel'`.

`handle.close()` and `close(id)` close with `'api'`. Escape, the overlay, the corner close button,
and a swipe close with `'dismiss'` and do not run the cancel handler. The timer closes with
`'timeout'`. `result()` resolves once with that reason, and calling it again returns the same
promise. The handle itself is not a promise.

`update` merges the next options into an open instance. An update after close does not reopen it.
Reusing an open `id` updates that instance in place and replays its entrance. `update` replaces
`action` and `cancel` as a whole, so include `onClick` again when the label changes.

Custom content has two entry points. `Toast.custom(render, options?)` supplies a render for that
call. `<Toast itemRender={render} />` supplies one for every other call on that host. A `.custom()`
render wins, then the host render, then the built-in layout. The render receives the id, the
resolved options, `pending()`, `action()`, `cancel()`, `close()`, `update()`, `index`, and
`expanded`. It replaces the inner content. The toast keeps its stack, swipe, timer, and live region.

A call without `host` goes to the host without an id and throws if only hosts with an id are
mounted. Pass `host` to target `<Toast id="alerts" />`.

### Methods

`show` is the neutral notice. `info`, `success`, `warning`, and `error` set the type. `loading` is
`show` with `type: 'loading'`. A loading toast stays open because of that type. After `update`
changes the type, the normal duration applies again.

```ts
Toast.show(options)
Toast.info(options)
Toast.success(options)
Toast.warning(options)
Toast.error(options)
Toast.loading(options)
Toast.promise(promise, { loading, success, error })
Toast.custom(render, options?)
Toast.update(id, options)
Toast.close(id?)
```

```tsx
Toast.success({ title: 'Project published', description: 'Your changes are now live.' })
Toast.error({ title: 'Upload failed', description: 'File size exceeds the 10 MB limit.' })
Toast.warning({ title: 'Low disk space', description: 'Volume is at 92% capacity.' })
Toast.info({ title: 'Update available', description: 'Version 2.4 is ready to install.' })
Toast.show({ title: 'Draft saved' })
```

### Action and dismissal

`action` is the primary button. `cancel: true` uses the locale label, and `cancel: { label }`
sets one. The corner button is shown when `closable` is set. Loading toasts hide the close button and
the progress bar.

```tsx
Toast.show({
  title: 'Conversation archived',
  action: {
    label: 'Undo',
    onClick: () => restoreConversation(),
  },
})
```

### Large layout

`large` moves the actions onto their own row and the close control to the top corner.

```tsx
Toast.success({
  title: 'Export finished',
  description: 'Your dataset is packaged and ready to download.',
  large: true,
  action: { label: 'Download', onClick: () => downloadFile() },
  cancel: { label: 'Dismiss' },
  closable: true,
})
```

`<Toast large />` applies that layout to every toast on the host.

### Promises

`promise` opens a loading toast and updates it when the promise settles. `loading`, `success`, and
`error` are the same options object used everywhere else. `success` and `error` may also be
functions of the settled value. When either is omitted, that outcome closes the toast with `'api'`.
The method returns the ordinary handle. Keep the original promise when you need the value.

```tsx
const task = deployProject()
Toast.promise(task, {
  loading: { title: 'Deploying project...' },
  success: { title: 'Deployment live!' },
  error: (err) => ({ title: `Deploy failed: ${String(err)}` }),
})
```

### Updates

```tsx
const handle = Toast.loading({ title: 'Exporting report...' })

Toast.update(handle.id, { title: 'Report ready', type: 'success' })

handle.close()
Toast.close()
```

### Duplicates

`preventDuplicate` compares the new toast with the front toast in the same host and corner. A match
bumps that toast and returns its handle. The option is a boolean on the host or on the call.

```tsx
Toast.info({
  title: 'Link copied to clipboard',
  preventDuplicate: true,
})
```

### Duration and progress

`duration` defaults to 4000 milliseconds. `progress` shows the remaining-time bar. Hovering the
list, leaving the window, or a pending action pauses the timer.

### Custom content

```tsx
Toast.custom((props) => (
  <div class="flex gap-4 items-center justify-between">
    <span class="text-sm">Maintenance scheduled in 10 minutes</span>
    <Button size="sm" variant="ghost" onClick={() => props.close()}>
      Dismiss
    </Button>
  </div>
))
```
